## §4 第4章 核心工作模式：把Claude Code变成真正的“生产力工具”

- **章节 UID**: 04
- **章节号**: §4
- **字数**: 10075
- **父模块**: 第二部分
- **原文出处**: `00-原书档案/fulltext/uid-04-核心工作模式：把Claude-Code变成真正的“生产力工具”.md`

> 📖 **原文**（§4.1）：Plan模式的作用很明确：Claude Code只负责规划，不执行。Claude Code会告诉你它打算怎么做，但不会修改代码、安装包或运行命令。

> 📖 **原文**（§4.2）：使用Claude Code一段时间后，你大概已经体会到那种“烦躁感”了：每次写文件都要确认，运行命令也要确认，安装依赖还要确认。

> 📖 **原文**（§4.7）：/clear命令比你想象的更重要。它会清空当前会话的所有对话历史，回到一个干净的起点。Claude Code启动时读取的CLAUDE. md和项目文件不受影响。

> 🧭 **归纳**：5 大工作模式：①Plan=只规划不执行，把分歧解决在方案阶段（防『边做边改』返工）；②Auto=AI 分类器替用户判断权限（>90% 安全操作自动放行，分类器漏检率仍 17%）；③/permissions=精细白名单可提交 Git；④worktree 让多实例并行；⑤/clear 是切任务神器。Auto ≠ `--dangerously-skip-permissions`。

## §5 第5章 CLAUDE.md：给AI一张地图

- **章节 UID**: 05
- **章节号**: §5
- **字数**: 5701
- **父模块**: 第二部分
- **原文出处**: `00-原书档案/fulltext/uid-05-CLAUDE.md：给AI一张地图.md`

> 📖 **原文**（§5.1）：用Claude Code写代码，你会接触到很多配置文件，比如package. json、tsconfig.json、.eslintrc等，但有一个文件，比它们加起来都重要，那就是CLAUDE.md。

> 📖 **原文**（§5.2）：新手写CLAUDE.md时，最常犯的错是试图写一本“百科全书”：把每个函数的用法、每个文件的作用、每个API的参数都塞进去。

> 📖 **原文**（§5.4）：CLAUDE.md不只是一个文件，还是一套层级系统。Claude Code会自动按顺序读取多个位置的CLAUDE.md。

> 🧭 **归纳**：CLAUDE.md = 智能体的『宪法』，每次启动自动读取，是跨会话持久记忆的唯一可靠载体。判断标准：Claude Code 能从代码里读出来的不写、猜不到的必须写；Boris 团队只用了 2500 token。飞轮规则：犯错→记录→迭代；项目级 + 全局级 + 子目录级三层结构，monorepo 模块隔离。

## §6 第6章 进阶对话技巧

- **章节 UID**: 06
- **章节号**: §6
- **字数**: 4695
- **父模块**: 第二部分
- **原文出处**: `00-原书档案/fulltext/uid-06-进阶对话技巧.md`

> 📖 **原文**（§6.1）：文件路径、技术选型和参考模式等越具体，Claude Code越知道该怎么执行，输出越精确。比如，不要说“做个登录功能”，要说“在src/auth/目录下新增Google OAuth登录功能，用Better Auth库，参考现有的GitHub登录实现方式”。

> 📖 **原文**（§6.2）：第11章将详细介绍harness工程的三层架构：prompt（提示词）、context（上下文）、harness（承载Claude Code运行的整个外部环境——CLAUDE.md、skill、hook、MCP、project结构都在这一层）。

> 📖 **原文**（§6.6）：Claude Code有4个effort级别——low、medium、high、max，用于控制Claude Code执行任务时投入多少推理资源。

> 🧭 **归纳**：4 条实用原则：①具体化（指明文件/场景/偏好）；②照本宣科（指已有范本而非描述）；③描述症状（不猜原因）；④一次只做一件事（不堆 3 件）。上下文管理核心：不是给所有信息而是给对的信息（2 万 token 已被 monorepo 基础配置占满）。Effort 永远默认 high：Boris 永不调低，因为 low 的返工成本远高于 high 省下的时间。
