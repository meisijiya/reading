# 《解构领域驱动设计》标准知识包

> **一句话**：张张逸的 DDD 方法体系全景——从软件复杂度的成因（规模/结构/变化）出发，诊断 Eric Evans 原版 DDD 的四点不足（缺乏统一过程/缺乏需求分析/缺乏架构体系/缺乏建模方法），提出「领域驱动设计统一过程（DDDUP）」三阶段：全局分析（价值需求+业务需求+子领域）→ 架构映射（系统上下文+限界上下文+上下文映射+菱形对称架构+领域驱动架构）→ 领域建模（分析建模+设计要素+服务驱动设计+实现建模），并以事件建模范式、DDD 魔方、领域驱动设计能力评估模型（DCAM）与参考过程模型（RPM）作为延伸体系。
