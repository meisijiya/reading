## 三、Claude Code 特色清单

### 3.1 commands（斜杠命令）

| 命令 | 用途 | 章节锚点 |
|---|---|---|
| `/clear` | 清空当前会话所有对话历史，回到干净起点；CLAUDE.md / 项目文件不受影响；纠正两次仍不对时果断用 | §4.7.2, §6 |
| `/plan` | 进入 Plan 模式；只规划不执行；输入提示词后 Claude Code 给出方案，可反复调整 | §4.1, §9 |
| `/permissions` | 预授权安全命令（白名单），可提交 Git 与团队共享——最精细最安全的方案 | §4.3.1 |
| `/cost` | 定期检查 token 消耗；Agent Teams / MCP 多开时必查 | §10 |
| `/context` | 查看上下文窗口使用情况；新会话仅加载 monorepo 基础配置就占 ~2 万 token，剩 18 万才是干活的空间 | §6 |
| `/batch` | 大规模并行 fan-out（替代手写 shell 脚本）；适合 50 文件重构 | §8 |
| `/proofreading` | 三遍审校 skill；审内容/风格/细节；Claude Code 看到关键词「审校」自动触发 | §10, §13 |
| `/compact` | 把当前对话压缩为摘要，适合长会话中途；⚠ Shrivu 提醒：处理不透明且易出错，优先用 /clear | §4.7.3, §6 |
| `/catchup` | `/clear` 之后让 Claude Code 读取当前 Git 分支变更，恢复上下文 | §6 |
| `/plugin` | 浏览 / 安装 plugin 市场（skill / hook / agents / MCP 配置一键安装） | §7 |
| `/voice` | 启动 Voice Mode（语音转文字，20+ 语言含中文）；按住空格键说话 | §4.6 |
| `/init` | 在项目目录下生成初始 CLAUDE.md 模板，加入 3 条自定义规则后新会话验证是否遵守 | §5 |
| `/btw` | 与 /compact 配合使用的辅助命令 | §4.7.3 |
| `--tmux` | 多智能体在 tmux 窗口启动，可用快捷键在不同实例间切换；Boris 设置 shell 别名快速跳转 | §8 |
| `--allowedTools "Edit,Bash(git commit *)"` | 命令行预授权工具白名单；用于并行启动多个 Claude Code 实例 | §8 |

### 3.2 shortcuts（键盘快捷键）

| 快捷键 | 用途 | 章节锚点 |
|---|---|---|
| `Shift+Tab`（双击） | 进入 Plan 模式；运行中按 `Shift+Tab` 循环切换 Normal → Auto-accept edits → Plan → Auto → Normal | §4.1, §4.3 |
| `Ctrl+C` | 退出 Claude Code 界面（建好测试目录后再进入） | §3 |
| 按住 `空格键` | Voice Mode 语音输入；松手后转文字发送 | §4.6 |
| `Cmd+Shift+X` / `Ctrl+Shift+X` | VS Code 扩展市场快捷键（安装 Claude Code 扩展） | §2 |
| tmux 内置快捷键 | `--tmux` 模式下在不同 Claude Code 实例间切换；Boris 用 shell 别名跳转 | §8 |

### 3.3 workflows（工作流模式）

| 工作流 | 用途 | 章节锚点 |
|---|---|---|
| **Plan 模式** | 只规划不执行；把分歧解决在方案阶段；防「边做边改」返工 | §4.1 |
| **Auto-accept edits 模式** | Claude Code 自动放行编辑类操作；适合方案已充分讨论后开启 | §4.3 |
| **Auto 模式** | AI 分类器替用户判断权限（>90% 安全操作自动放行）；漏检率仍 17% | §4.3 |
| **Normal 模式** | 默认模式；每次操作需确认；适合初学者熟悉 Claude Code | §4 |
| **/permissions + Git** | 精细白名单预授权；可提交 Git 与团队共享；最精细最安全 | §4.3.1 |
| **worktree 并行** | 同仓库多分支独立工作目录；Boris 5 本地 + 5–10 云端同时推进十几任务 | §4.5, §8.1 |
| **subagent（专家）** | 当前任务内调「专家」处理特定环节（如安全审查专家评估认证代码）；独立上下文 | §8.3 |
| **Agent Teams** | Writer / Reviewer 自协调；不是用户协调多个智能体，是智能体自己协调；2026.2 GA；TDD 模式适用 | §8.4, §11.5 |
| **MCP + Slack 经典用法** | bug 报告 → Claude Code 自动读描述 → 找代码 → 修复 → 提交 PR → Slack 回复「已修复，PR 链接在这里」；全程零人工 | §7.4 |
| **5 阶段产品方法论** | Phase 0 采访 → Phase 1 初始化 → Phase 2 Plan 实现 → Phase 3 截图反馈 → Phase 4 自动化 → Phase 5 部署 | §9 |
| **三遍审校 /proofreading** | 审内容 → 审风格（六大 AI 味）→ 审细节；AI 检测率 60%+ → 30% 以下 | §13 |
| **Fan-out** | /batch 或 `for + &`：50 文件 → 50 智能体几分钟完成大规模重构迁移 | §8 |
| **「犯错 → 记录 → 迭代」飞轮** | 告诉 Claude Code「记住这个坑」→ 自动写入 CLAUDE.md → 下次主动避开 | §5.5, §11.3 |

### 3.4 patterns（结构模式）

| 模式 | 用途 | 章节锚点 |
|---|---|---|
| **CLAUDE.md 三层结构** | 项目级（团队 Git 共享）+ 全局级（~/.claude/CLAUDE.md）+ 子目录级（monorepo 模块隔离）；Claude Code 自动按顺序读取 | §5.4 |
| **skill / hook / MCP 三机制** | skill 教做事（SOP 文档，对 Claude Code 的「建议」）；hook 强制执行（生命周期事件触发 shell，跳过不了）；MCP 连接外部（USB 接口） | §7 |
| **Chrome MV3 三层架构** | background.js（指挥中心：chrome.alarms 扫描循环 + 消息路由）+ content.js（薄壳 175 行：只读 cookie + 操作 DOM）+ lib/（7 个业务模块独立可测） | §12.3 |
| **CLAUDE.md 路由系统** | 根 CLAUDE.md ≤8KB 按关键词分发到子工作区规则文件；一个入口多个出口；解决多场景（写作/开发/视频）同时维护问题 | §13.1 |
| **TAOR 循环** | think → act → observe → repeat；Claude Code 的「心脏」；每次只调用一个工具 | §11.3.1 |
| **Auto 分类器 3 级风险** | low（读文件直接放行）/ medium（写配置文件）/ high（用户确认）——Auto 模式不是简单全放行 | §11.3.4 |
| **Boris 「每天一次就写成 skill」** | 判断标准：一件事每天做超过一次 → 写 skill 或 command；激进版：出现过两次就写 | §7.1 |
| **已知坑即规则** | 告诉 Claude Code「记住这个坑」→ 自动写入 CLAUDE.md 的「已知坑」部分 → 下次主动避开 | §11.3 |
| **CLAUDE.md 与 MEMORY.md 并行** | 手写 CLAUDE.md（团队规则）+ 自动记忆 ~/.claude/projects/<项目>/memory/MEMORY.md（Claude Code 自学） | §5.5 |
| **内部架构 Bun + React/Ink + TS + Zod** | Claude Code 运行在 Bun（而非 Node.js）；React/Ink 终端 UI；严格 TypeScript；Zod Schema 验证；入口 785KB | §11.3.2 |
| **具体化 / 照本宣科 / 描述症状 / 一次一事** | 4 条对话原则：指明文件路径与场景 / 指已有范本而非描述 / 不猜原因只描述现象 / 不堆 3 件事 | §6 |
| **Effort 永远默认 high** | Boris 永不调低——low 的返工成本远高于 high 省下的时间 | §6.6 |
