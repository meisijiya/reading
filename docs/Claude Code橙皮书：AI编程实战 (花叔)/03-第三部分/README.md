> 📖 **原文**（§7.1）：我一开始以为，安装好Claude Code直接使用就行。后来发现自己总在进行重复操作：每次提交代码前都要提醒先进行lint检查，每次新建组件都要交代一遍项目规范，每次查数据都要手动复制SQL结果并粘贴给Claude Code……

> 📖 **原文**（§7.3）：skill有一个天然的局限：它本质上是对Claude Code的“建议”。Claude Code会尽量遵守，但遵从率不是100%，尤其是在长对话的后期，它可能就忘了。

> 📖 **原文**（§7.4）：skill教Claude Code知识，hook保证执行的确定性，但它们都在Claude Code的内部世界运作。如果你想让Claude Code直接查数据库、调用API、读取设计稿，就需要MCP。

> 🧭 **归纳**：3 种扩展机制分工：skill 教做事（SOP 文档）、hook 强制执行（生命周期事件触发 shell）、MCP 连接外部世界（USB 接口）。关键区别：CLAUDE.md 和 hook 都是『指令』，但 CLAUDE.md 是自然语言建议（会被压缩遗忘），hook 是平台级强制（Claude Code 跳过不了）。MCP + Slack 经典用法=bug 报告→修复→PR→回复全程零人工。

## §8 第8章 多智能体协作

- **章节 UID**: 08
- **章节号**: §8
- **字数**: 6580
- **父模块**: 第三部分
- **原文出处**: [`uid-08-多智能体协作.md`](../00-原书档案/fulltext/uid-08-多智能体协作.md)

> 📖 **原文**（§8.1）：Boris日常是这样工作的：本地开启5个Claude Code实例（每个实例对应一个独立的git checkout工作目录，互不干扰），云端再打开5～10个Claude网页会话，每个会话执行不同的任务，包括写新功能、修复bug、写测试、做重构、进行代码审查等，同时进行。

> 📖 **原文**（§8.3）：并行智能体适合处理互不相关的独立任务。但有时你要的不是打开一个新窗口，而是在当前任务中调一个“专家”来处理特定环节，比如让一个安全审查专家评估你刚写的认证代码。

> 📖 **原文**（§8.4）：Agent Teams于2026年2月正式发布，目前是Claude Code最强大的协作模式。它的核心理念很简单：不是由用户协调多个智能体，而是让智能体自己协调。

> 🧭 **归纳**：多智能体三层=worktree（并行基础设施：Boris 5 本地 + 5-10 云端）→ subagent（独立上下文空间的『专家』）→ Agent Teams（Writer/Reviewer 自协调，TDD 模式）。并行不是越多越好：6 智能体=6 倍 token 消耗+写作风格不一需审校。Fan-out（/batch 或 `for + &`）适合大规模重构迁移：50 文件→50 智能体几分钟。

## §10 第10章 避坑指南：AI编程的边界

- **章节 UID**: 10
- **章节号**: §10
- **字数**: 2395
- **父模块**: 第三部分
- **原文出处**: [`uid-10-避坑指南：AI编程的边界.md`](../00-原书档案/fulltext/uid-10-避坑指南：AI编程的边界.md)

> 📖 **原文**（§10.1）：有一次，我让Claude Code帮我查一个AI产品的最新定价，它非常自信地给了我一组数字，我直接写进了文章。发布之后，读者指出：定价不对，那是3个月前的价格。

> 📖 **原文**（§10.2）：Agent Teams是我用过最强大的功能之一，但也是最贵的。每个智能体维护独立的上下文窗口，整体词元消耗量是单会话的6～8倍（具体取决于子任务数量和上下文复用率等）。

> 📖 **原文**（§10.4）：使用Claude Code半年之后，我发现自己有时候会不加思考地接受它的方案。因为之前它给的方案大多数是对的，所以我开始偷懒，不去想“为什么用方案A而不用方案B”。

> 🧭 **归纳**：4 大陷阱：①『自信错误』=Claude Code 不会说不知道，数据/日期/定价必须 Web Search（写 CLAUDE.md 第一条）；②『词元成本』=Agent Teams 6-8× 单会话、MCP 工具描述占 15% 上下文（/cost + /context 定期检查）；③『AI 味』=破折号/排比三连/假设性开头（必须三遍审校 skill 把 AI 检测率从 60% 降到 30%）；④『丧失判断力』=方向性决策必须自己来（Anthropic 报告：60% 工作用了 AI，仅 0-20% 任务可完全委托）。

> 📖 **原文**（§11.4）：Boris曾公开表示，自己超过90%的代码由Claude Code生成。他的日常工作更多是描述需求、审查输出、做架构决策。
