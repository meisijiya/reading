# 第十章 多 Agent 协作

> AI 系统的终极形态：多 Agent 协作。**群体的智能可以高于个体**——人类文明就是明证。本章从分类框架 → 何时真正优于单 Agent → 共享/不共享上下文 → 失败模式 → Agent 社会。

## Q10-1 多 Agent 协作的分类框架是什么？两维度

- 章节: ch011 §10.1
- 主题: 分类框架

> 📖 **原文** (ch011 §10.1)： 要构建多 Agent 系统，首先需要理解两个核心设计维度，它们共同决定了系统的基本架构和实现方式。

🧭 **归纳**（两维度四象限）：

**维度一：上下文是否共享**
- **共享上下文**：后一个 Agent 接收前一个的完整轨迹；切换 system prompt + 工具集 → 变新 Agent；信息零损耗但上下文可能爆炸
- **不共享上下文**：每个 Agent 独立上下文；通过显式通信传递（工具参数 / 共享文件系统 / 消息总线）

**维度二：协作拓扑**
- **对等协作（Peer）**：固定拓扑 + 迭代改进（如论文写作 = 起草者 + 评论者）
- **管理者模式（Orchestration）**：中心 Manager 负责规划调度，多子 Agent 负责子任务
- **去中心化（Decentralized）**：无中心控制者，Agent 互相沟通协作

|  | 共享上下文 | 不共享上下文 |
|---|---|---|
| **对等** | 论文 Agent = 起草者 → 评论者（共享轨迹迭代） | 翻译流水线（Glossary → Translation，互传文件） |
| **管理者** | Manager 切换角色（triage/research/coding/writing） | Manager spawn 子 Agent、各跑各的 |
| **去中心化** | （少见） | 多个 Agent 互发消息（如 Agent 社会） |

## Q10-2 多 Agent 何时真正优于单 Agent？"新信息"判据

- 章节: ch011 §10.2
- 主题: 何时多 Agent

> 📖 **原文** (ch011 §10.2)： 在进入具体的协作架构之前，先回答一个更根本的问题：**什么时候真正需要多个 Agent，什么时候一个 Agent 就够了？** 这个问题的答案会成为后文所有工程方案的总体参照。近年的一系列研究给出了一个清晰的判断框架——**核心判据只有一条：协作过程是否引入了单个 Agent 在生成时无法获得的新信息？** 表10-2 汇总了不同协作模式是否引入新信息，用来判断多 Agent 协作相对单 Agent 是否具有实质价值。**审核者使用测试执行结果审查代码——是（执行反馈）——显著提升**。**审核者查看渲染截图审查前端/PPT 代码——是（视觉反馈）——显著提升**。**审核者使用外部工具验证事实——是（工具反馈）——显著提升**。**同一模型自我审查（重新阅读自己的输出）——否——通常无效甚至有害**。**不同 Agent 辩论同一段文本——否——在等计算量下与单 Agent 持平**。这个"新信息"框架解释了一个看似矛盾的现象：一些学术研究认为多 Agent 并不能提升 Agent 能力上限，但工程实践中多 Agent 确实效果更好。矛盾的根源在于两者讨论的是不同类型的"多 Agent"。

🧭 **归纳**（多 Agent 价值的"新信息"判据）：

| 协作模式 | 引入新信息？ | 效果 |
|---|---|---|
| 同一模型自我审查 | ❌ 否 | 通常无效甚至有害 |
| 不同 Agent 辩论同一段文本 | ❌ 否 | 等算力下单 Agent 持平 |
| 审核者用**执行结果**审查代码 | ✅ 是（执行反馈） | 显著提升（RLEF） |
| 审核者用**视觉反馈**审查前端/PPT | ✅ 是（视觉） | 显著提升（WebGen-Agent 26.4% → 51.9%） |
| 审核者用**外部工具**验证事实 | ✅ 是（工具反馈） | 显著提升 |

➕ **补充**：**步骤预算感知**——单纯增加步骤数不保证性能↑（Budget-Aware 研究）；Agent 需"预算意识"，根据剩余资源动态调整策略（前期广泛探索，后期聚焦深挖）。

## Q10-3 共享上下文 vs 不共享上下文怎么选？Skill 还是 transfer_to_agent

- 章节: ch011 §10.3
- 主题: 共享 vs 不共享

> 📖 **原文** (ch011 §10.3)： 这里有一个常被忽略、但会直接改变架构的设计选择： **角色转换究竟是替换 system prompt，还是加载 Skill？**

🧭 **归纳**：

| 选择 | 适用 |
|---|---|
| **transfer_to_agent**（替换 system prompt + 工具集） | 角色差异涉及**权限/工具隔离/合规边界/需要硬禁止**某类动作 |
| **Skill**（固定 system prompt，按需加载） | 角色差异主要是**知识/流程/写作风格** |

**多 Agent 系统 = 操作系统的镜像**：

| 操作系统 | 多 Agent 系统 |
|---|---|
| 程序（可执行文件） | 静态前缀（system prompt + 工具定义） |
| 进程的内存 | 轨迹 |
| CPU | LLM |
| 内核 | Agent 运行时 |
| 系统调用 | 工具调用 |
| fork | spawn_subagent |
| kill | cancel_subagent |
| ps | list_agents |
| 退出码 + wait() | 子 Agent 返回的结构化摘要 |
| 共享内存 / 消息传递 | 共享文件系统 / 消息 |

## Q10-4 Agent 眼中的虚拟文件系统

- 章节: ch011 §10.4.1
- 主题: 虚拟文件系统

🧭 **归纳**（虚拟文件系统四类区域）：

| 区域 | 生命周期 | 可见性 | 用途 |
|---|---|---|---|
| **Agent 专属工作区（Scratchpad）** | 与实例绑定 | 私有 | 中间产物/临时文件/调试日志——避免 Agent 试错污染主上下文 |
| **多 Agent 共享空间（Shared Workspace）** | 与任务绑定 | 多 Agent 共享 + 用户可见 | Agent 间交换产物的主媒介；并发冲突高发区（乐观锁/worktree） |
| **外部挂载资源（Mounted）** | 与用户授权绑定 | 按外部权限 | Google Drive/Notion/Dropbox；延迟高、一致性弱、**写回需谨慎**（避免污染用户真实数据） |
| **系统内置资源（Built-in）** | 跨会话稳定 | 全局只读共享 | Skills、参考手册、模板库——按渐进式披露取用 |

## Q10-5 多 Agent 协作的四大失败模式

- 章节: ch011 §10.5
- 主题: 失败模式

🧭 **归纳**（四大失败模式）：

| 失败模式 | 表现 | 解法 |
|---|---|---|
| **共享文件系统的并发冲突** | 多个 Agent 同时写一个文件，后写覆盖先写 | 乐观锁、worktree 隔离、版本号 |
| **错误的级联放大** | 一个 Agent 错了，错误沿调用链传到下游 | 每步独立验证（不要信任上游结论）+ 断路器 |
| **过早终止与循环失控** | Agent 过早宣布完成 / 反复在同一步循环 | 验证环节 + 进度状态栏（参考 Q2-9）+ 循环检测 |
| **理解债与认知投降** | Agent 累到放弃思考 → 接受错误前提 | 上下文压缩 + 知识沉淀 + 工具/任务拆分（避免单个 Agent 承担过多） |

## Q10-6 Agent 社会：前沿方向

- 章节: ch011 §10.6
- 主题: Agent 社会

> 📖 **原文** (ch011 §10.6)： 前面三节讨论的都是目标明确的任务协作。接下来将视角转向一个更开放的问题：**当 Agent 数量从几个扩展到成百上千、交互足够自由时，会涌现出什么行为？** 本节的案例可以从三个维度来理解：**社交涌现**：涌现行为（Emergent Behavior）是指系统整体表现出的、无法从单个个体的行为规则中直接预测的集体行为模式。斯坦福 AI 小镇展示了 25 个 Agent 如何自组织社交活动，Agentopia 把模拟时间尺度从"天"拉长到 10 年，Moltbook 则把规模推到 150 万。**经济涌现**：Agent 通过市场机制进行资源分配和任务协调。Vending-Bench Arena 让多个 Agent 在同一市场中竞争经营，Pinchwork 和 RentAHuman 则构建了 Agent 之间（以及 Agent 与人类之间）的经济交易市场。**策略博弈**：Agent 在规则约束下进行推理、欺骗和社交操控。狼人杀实验考验的是 Agent 在信息不对称条件下的策略涌现。**Agent 社会**与**Agent 经济**是 AI 系统的终极形态方向。

🧭 **归纳**（Agent 社会四个里程碑案例）：

| 项目 | 范式 | 意义 |
|---|---|---|
| **斯坦福 AI 小镇** | 生成式 Agent 社会模拟 | 25 个 Agent 在虚拟小镇中自发形成社交/工作/生活模式 |
| **Agentopia** | 十年尺度长期生活模拟 | 探索 Agent 长期演化与文化形成 |
| **Moltbook** | Agent 自己的社交网络 | Agent 拥有独立社交圈层 |
| **Vending-Bench Arena** | Agent 经济竞争 | 多个 Agent 在市场环境里做买卖决策；测试长期经济策略 |
| **Pinchwork / RentAHuman** | Agent 经济基础设施 | Agent 雇佣人类 / 雇佣其他 Agent 完成物理世界任务 |
| **狼人杀** | 信息不对称策略博弈 | 测试 Agent 在不完美信息下的推理与社交博弈 |

➕ **补充**：**信息不对称下的策略博弈**（狼人杀）= 长期被低估的 Agent 能力测试场——要求 Agent 在隐藏身份、读人/读 Agent、欺骗与反欺骗之间做权衡，比单纯 LLM benchmark 更接近真实社会。
