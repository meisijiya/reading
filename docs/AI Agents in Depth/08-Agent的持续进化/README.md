# 第八章 Agent 的持续进化

> 把"会完成任务"推向"能够可靠工作"的关键能力。**保存经历不等于从经历中学习**——学习发生在"评价、对照、归纳、验证"之后。

## Q8-1 为什么"保存经历 ≠ 从经历中学习"？持续进化的起点是什么？

- 章节: ch009 §8.0-8.1
- 主题: 评价起点

> 📖 **原文** (ch009 §8.0)： 能否 **自主从经验中学习** ，正在成为 Agent 从"会完成任务"走向"能够可靠工作"的关键能力 …… 部署后的模型并不会因为一次推理自动改变参数 …… **保存经历不等于从经历中学习** 。把一百条轨迹放进长上下文或向量库，可以帮助模型在需要时找回某个案例，却不会自动完成跨案例比较 …… 学习发生在系统主动完成"评价、对照、归纳、验证"之后，而不是发生在日志写入磁盘的那一刻。

> 📖 **原文** (ch009 §8.1)： 持续进化的起点不是"总结"，而是 **"评价"** 。如果系统不知道任务是否完成，也不知道哪一步造成了成功或失败，那么语言模型生成的反思只能是一种猜测 …… **结果正确并不代表过程正确** 。删除失败的测试用例也能让测试通过 …… **可靠评价既要看结果，也要检查达成结果的路径** 。

🧭 **归纳**：
- **三层验证结构**：
  - 底层：**结果验证器**（环境真值：测试结果/数据库状态/工具返回）——"事情是否真的办成"
  - 中层：**过程验证器**（业务规则/权限/动作序列）——"是否以允许的方式办成"
  - 上层：**质量验证器**（基于 Rubric 评价语言与策略）——"是否办得合适"
- 验证结果 **不应被压缩成一个标量**——应保留"哪里错、为什么错、证据在哪里"的结构化诊断
- LLM 验证器本身需校准（专家标注轨迹 + 高风险/低置信度案例由第二模型或人工复核 + 模型变更重测）

## Q8-2 客服 Agent 轨迹评价的七个维度是什么？

- 章节: ch009 §8.1 + 表8-1
- 主题: 评价维度

🧭 **归纳**（客服 Agent 轨迹评价七维度）：

| 维度 | 验证问题 | 主要证据 |
|---|---|---|
| **任务结果** | 核心诉求是否解决 | 最终环境状态、工具结果 |
| **规则遵从** | 是否违反政策/权限/必要流程 | 政策库、动作轨迹 |
| **隐私边界** | 是否泄露不应提供的信息 | 回复文本、数据访问记录 |
| **事实可靠性** | 陈述是否有知识/工具结果支持 | 引用来源、工具返回 |
| **承诺-行动一致性** | 声称完成的操作是否真实发生 | 回复与工具日志对照 |
| **表达质量** | 自然、简洁、避免重复模板 | 对话全文、语言 Rubric |
| **合规变通** | 原方案不可行时是否找合法替代 | 用户目标、政策、后续动作 |

➕ **补充**：**"承诺-行动一致性"尤其适合 Agent 场景**——传统文本评价只读最终回复，轨迹评价继续检查是否真调用了工具、是否成功、订单是否真改。

## Q8-3 Agent 持续进化的四种方法是什么？四载体对比

- 章节: ch009 §8.2
- 主题: 四种更新方式

> 📖 **原文** (ch009 §8.2)： 选择更新方式的首要依据不是经验出现了多久，而是 **目标能力能否被某种载体自然表达** 。事实和经验适合写成知识文档；可以清楚语言化的策略适合写入提示词或 Skill；可以精确执行的流程与约束适合写成程序；感知、语言风格和隐式策略等高维能力则必须进入模型参数。

🧭 **归纳**（四载体对比）：

| 更新方式 | 适合承载 | 主要优势 | 主要局限 |
|---|---|---|---|
| **经验知识库** | 事实、经验规律、例外与来源 | 更新快、可追溯、可按需检索 | 依赖检索和模型正确应用 |
| **Prompt 与 Skill** | 需理解语境/例外/优先级的判断原则 | 可解释、作用范围可控 | 容易膨胀、冲突或被忽略 |
| **程序与 Harness** | 可确定解析、可执行验证、高风险硬约束 | 可测试、执行稳定、成本低 | 开发与维护成本高 |
| **模型参数** | 高维感知、生成风格、隐式策略 | 泛化能力强、推理开销低 | 更新与回归成本高 |

**四者不互斥**：医疗影像 Agent 用参数识别病灶 + 知识库提供最新指南 + 代码计算风险指标。

## Q8-4 经验沉淀为知识的两阶段方法是什么？

- 章节: ch009 §8.2.1
- 主题: 知识沉淀

> 📖 **原文** (ch009 §8.2.1)： 原始轨迹不适合作为正式知识单元 …… 更稳妥的系统保留三层数据： **不可变的原始轨迹** 用于审计， **单次运行分析** 记录本次成败与经验草案， **多条同类轨迹** 再被比较、聚类和归纳，形成面向未来的 Markdown 知识文档 …… 把记录与整理分开，可以避免一次偶发成功或网络故障立即改变 Agent，也使系统能够在看到多条成功和失败后再判断共性。

🧭 **归纳**（知识提炼五步管道）：
1. **保存不可变轨迹 + 环境结果**
2. **单次运行分析**：任务类型/所需能力/观察到的策略/错误与例外
3. **按任务族聚合同类运行**：为每条经验草案建立"哪些轨迹支持、哪些轨迹反驳"的证据表
4. **达到支持门槛才写正式文档**
5. **未参与提炼的新任务上测试迁移效果**（不见任务表现↑不算学会）

**正式知识与草案分析分库存放**——可重新归纳不篡改原始证据；环境版本变化时可精确撤销某条结论。

## Q8-5 经验写成指令：系统提示学习（System Prompt Learning）怎么做？

- 章节: ch009 §8.2.2
- 主题: 提示词优化

> 📖 **原文** (ch009 §8.2.2)： 经验知识库给 Agent 提供"可以参考的资料"，Prompt 和 Skill 则规定"应该怎样行动"。当多条相似轨迹反复暴露同一种策略错误，而且错误能够用语言清楚描述时，才值得把经验提升为指令。这里先把三个概念分开：**系统 Prompt 对所有任务生效，Skill 只在匹配到某个领域或工具时按需加载，程序/Harness 负责权限和其他硬约束。** **Andrej Karpathy 将这种做法称为系统提示学习**（System Prompt Learning）：模型遇到问题后，用一句清楚的话提醒未来的自己。DSPy 在开发集上搜索指令和示例；OPRO 根据历史提示词及其得分提出提示提案；GEPA 从失败轨迹的自然语言反思中生成并筛选提示提案。这些方法适合离线批量优化；生产环境更适合使用可审计的最小更新提案，并保留快速回滚路径。**修改应是带来源的最小 diff**，而不是让模型每次都重写整份 Prompt。**待验证版本必须同时在触发失败的边界集和正常工作的保留集上测试，前者要改善，后者不能退化。**

🧭 **归纳**：
- **三类指令载体**职责分明：
  - **系统 Prompt**：对所有任务生效
  - **Skill**：只在匹配到某领域/工具时按需加载
  - **程序/Harness**：负责权限和其他硬约束
- **系统提示学习 ≠ 提示工程**——第二章讲"组织一份好 Prompt"；这里讲"什么反馈足以触发修改、怎样安全发布"
- **更新原则**：带来源的最小 diff（不是让模型重写整份 Prompt）；边界集↑ + 保留集不退化

## Q8-6 可验证闭环的边界：当"完成"不等于"进步"

- 章节: ch009 §8.3.3
- 主题: 闭环边界

> 📖 **原文** (ch009 §8.3.3)： 前面的闭环在 Coding、工具调用和业务状态变更等任务上最容易成立，因为测试、环境状态或确定性规则能够快速给出反馈。开放式科研、战略规划和复杂产品设计则不同：评价信号来得慢，正确答案不唯一，真正重要的目标——研究品味、长期价值、可维护性——还很难写成一个即时分数。**可验证闭环的边界：当"完成"不等于"进步"**。"完成"是这一次任务的执行结果，"进步"是模型/系统在多次任务上能力的可观察改善。把"完成"等同于"进步"是危险的。**循环每转一圈之所以有真实的进步，是因为验证环节把外部世界的观测写回了上下文，注入了模型自己想不出来的新信息**；抽掉这一步，循环只是让模型把旧信息在原地翻来覆去地重新排列。**业界"循环的瓶颈在验证器，而不在模型"的共识**，与上面括号里那条发现说的是同一件事。

🧭 **归纳**：
- **"完成" ≠ "进步"**——完成是单次任务结果；进步是多次任务上能力的可观察改善
- 循环真正的进步 = 验证环节把 **外部世界观测** 写回上下文（注入新信息）
- 没有外部验证 → 循环只是把旧信息原地翻来覆去
- 业界共识：**循环的瓶颈在验证器，而不在模型**

## Q8-7 持续进化的安全边界

- 章节: ch009 §8.3.4
- 主题: 安全边界

🧭 **归纳**（持续进化安全四件套）：
1. **不可绕过原始证据**——更新永远基于可追溯的运行数据
2. **小变更 + 灰度**——避免一次大改全量生效
3. **保留集不退化**——已有任务在更新后表现不能变差
4. **安全红线**：删除/越权/对外发信等高风险操作不进自动学习闭环

➕ **补充**：**睡眠学习**（§8.3.5）——前台交互期间不断累积新证据和局部更新；后台在周期性窗口里暂时拉远视角，重新审视整个知识体系（类似人类的"睡眠巩固记忆"）。
