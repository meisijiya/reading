# 第七章 模型后训练

> 优化 LLM 这个"大脑"——通过后训练让模型更好地利用上下文和工具。**评估体系与仿真环境是后训练的两块基石**。两条贯穿主线：**SFT 记忆，RL 泛化** + **数据和环境比算法更重要**。

## Q7-1 现代模型能力开发的三个阶段是什么？

- 章节: ch008 §7.0
- 主题: 三阶段全景

> 📖 **原文** (ch008 §7.1)： 引言给了三阶段的地图，这一节把每一步的机制讲透。三个阶段用的**数据**、**优化目标**、**代价**各不相同，理解它们的异同，是读懂整章的钥匙。表7-1 先给一个总览，随后逐项展开。预训练用海量原始互联网文本做"预测下一个词"——SFT 用几千到几万条"输入-输出"示范对继续做"预测下一个词"（loss masking 只在回答上算损失）——RL 用任务、环境和奖励信号最大化期望奖励。一个直觉类比：**预训练是"读万卷书"（积累知识），SFT 是"老师手把手教标准解法"（模仿示范），RL 是"自己下场做题、根据对错反复打磨"（试错提升）**。现代大模型的全部"智能"，都建立在一个简单到令人意外的任务上：**预测下一个词**（Next Token Prediction，NTP）。

🧭 **归纳**（三阶段总览）：

| 阶段 | 数据 | 优化目标 | 学到什么 | 代价 |
|---|---|---|---|---|
| **预训练** | 海量互联网文本 | 预测下一个词 | 语言规律、世界知识、基本推理 | 极高（数千万美元） |
| **SFT** | 几千~几万条"输入-输出"示范对 | 预测下一个词（loss masking 仅算在回答上） | 指令遵循、格式、风格、流程协议 | 低（几小时~几天） |
| **RL** | 任务 + 环境 + 奖励信号 | 最大化期望奖励 | 可迁移的决策策略、新解法 | 高（常是 SFT 几十~上百倍） |

## Q7-2 SFT 的本质是什么？为什么容易"记忆"而非"泛化"？

- 章节: ch008 §7.1.2 + §7.1.4
- 主题: SFT 本质

> 📖 **原文** (ch008 §7.1.2)： **SFT 在数学上和预训练是同一个任务——都是预测下一个词、最小化同一个损失函数** …… 很多初学者以为 SFT 是一种全新方法，其实不是。SFT 与预训练的差别只有两点： 1. **数据不同** …… 2. **损失只算在"回答"上（loss masking）** …… 一句话概括 SFT 的本质： **用极高的样本效率，把一套稳定的"输入→输出"映射与协议固化进参数** 。它固化的是"格式、风格、流程"这类 **协议性知识** （该怎么说、怎么做），而非大量 **事实性知识** （知道什么）——后者要靠预训练或 RAG。

🧭 **归纳**：
- SFT ≠ 新方法；SFT = 换数据 + loss masking 的"预测下一个词"
- 优化目标 = 最大化标注答案的 token 概率（**极大似然**）
- 倾向于 **mass-covering**（覆盖式）—— 复现示范的所有模式
- 几千条样本就能见效（**高样本效率**）
- **工程默认**：LoRA（低秩适配）—— 不动原始权重，只挂 1-5% 参数的"补丁"；最优学习率约是全参微调的 10 倍；SFT 用中高 rank（64-256）

## Q7-3 什么时候需要先 SFT 后 RL？"先形后神"原则

- 章节: ch008 §7.1.3
- 主题: 顺序决策

> 📖 **原文** (ch008 §7.1.3)： 所以在结构化输出不稳定的设置中，SFT 可以先扮演 **"把话说利索"** 的角色：用少量示范让输出格式稳定、能被可靠解析，RL 才有一个能打分的起点。这是业界稳健的"先 SFT 后 RL"两阶段范式。在这种设置中跳过 SFT 直接做 RL，输出不稳定可能让奖励信号变成噪声、导致训练失败。**借用中国画的说法：SFT 先把"形"（格式、结构）立起来，RL 再追求"神"（策略、泛化），即先形后神。** 一个重要边界："必须先 SFT"是在"**较小基础模型 + 严格结构化输出**"的设定下成立的。实验 7-11 会看到，Llama-3.2-Vision-11B 这个量级不经 SFT 直接 RL 会完全失败。但若基础模型足够强，它可能一上来就能产出够格的输出，从而跳过 SFT——**DeepSeek-R1-Zero 就证明了强基模可以直接 RL 成功**，自行涌现出反思与长链思考。代价是输出可读性差、中英文混杂，所以 DeepSeek 最终仍在 R1 里加回"冷启动 SFT"，把"形"重新立稳。**R1 从 Zero 到冷启动的往返，正是"先形后神"的最好注脚。**

🧭 **归纳**：

| 条件 | 推荐 |
|---|---|
| 较小基础模型 + 严格结构化输出 | **必须先 SFT**（让格式稳定可解析） |
| 强基模（R1-Zero）+ 可接受输出瑕疵 | 可直接 RL（自行涌现长链思考） |
| 实际生产 | **几乎都先 SFT 后 RL**（R1 最终仍加"冷启动 SFT"） |

## Q7-4 SFT vs RL 的本质区别是什么？

- 章节: ch008 §7.1.4 + 表7-2
- 主题: SFT vs RL

> 📖 **原文** (ch008 §7.1.4)： 现在解释这种倾向为什么可能出现，关键在于两者的 **优化目标不同** ： **SFT 最大化标注回答的概率** …… **RL 最大化期望奖励** 。模型探索多条路径，并提高高奖励路径的概率。当奖励忠实反映目标、探索也足够时，模型可能发现示范中没有的可迁移策略 …… 打个比方： **SFT 细致学习已有地图，RL 则可以拿着奖励这枚指南针探索地图外的候选路线** 。 地图或指南针不准都会迷路。因此许多系统先用 SFT 建立稳定起点，再在奖励与环境足够可信时加入 RL。

🧭 **归纳**：

| 维度 | SFT | RL |
|---|---|---|
| 优化目标 | 最大化标注答案概率（极大似然） | 最大化期望奖励 |
| 训练信号 | 逐 token 监督 | 策略生成 + 标量奖励（结果级或步骤级） |
| 数据 | "输入-输出"示范对 | 任务 + 环境 + 奖励信号 |
| 概率分布 | **mass-covering**（覆盖式） | **mode-seeking**（寻峰式） |
| 分布漂移 | 取决于示范覆盖；本章实验常过拟合 | 本章实验中迁移更好 |
| 样本效率 | 高（几千条） | 低（SFT 的几十~上百倍） |
| 稳定性 | 高、收敛快 | 低、易震荡 |
| 最适合 | 固化格式/风格/流程 + 高质量示范 + 环境稳定 | 泛化新场景 + 探索最优策略 + 标注成本过高 |

## Q7-5 奖励设计的关键决策：来源、时机、信息量

- 章节: ch008 §7.11
- 主题: 奖励设计

> 📖 **原文** (ch008 §7.11.1-7.11.3)： 最可靠的来源是**可验证奖励（RLVR）**：用测试用例、数据库断言、状态差异或格式检查直接判断结果。数学答案、代码测试和结构化工具调用都适合从二元结果奖励开始；规则越确定，奖励越便宜、可复现，也越不容易被模型钻空子。**奖励来自哪里、奖励在什么时候给、奖励需要表达多少信息——这三个维度合起来，决定了训练能不能学到你想学的东西，也决定了模型会"找捷径"的难易程度。** 选择原则很直接：有确定答案或测试，优先二元标量；有多个相互独立的质量目标，使用向量，或将各维度加权成标量；开放式、难以穷举规则，使用生成式诊断，但要配合事实校验和人工抽检。**不要为了"奖励更丰富"而堆叠不可验证的维度。** 每增加一个评价维度，就增加一种被策略钻空子的可能。

🧭 **归纳**（奖励三维决策）：

| 维度 | 选项 | 含义 |
|---|---|---|
| **来源** | 规则 / 人类偏好 / 模型评判 | 真实性、可扩展性、成本不同 |
| **时机** | 结果级 / 过程级 | 结果对但过程错（破坏性捷径）→ 加 RLVP（验证路径惩罚） |
| **信息量** | 标量 / 向量 / 生成式诊断 | 标量最简单；向量分维度；生成式诊断最强也最易被 hack |

**RLVP（路径约束 + 验证路径惩罚）** = 奖励结果、约束过程——对过程中可验证的违规动作（如 rm -rf、未授权写）施加额外惩罚，把"不用破坏性手段"内化为模型常识。

## Q7-6 蒸馏：On-Policy Distillation 让一次 rollout 产生密集监督

- 章节: ch008 §7.12
- 主题: 蒸馏

> 📖 **原文** (ch008 §7.12)： On-Policy Distillation：让一次 rollout 产生密集监督。让较弱学生按当前策略 rollout，在每一步拿教师模型对相同前文的分布作 soft target。这样一次轨迹就能产出大量监督信号，把宝贵的交互算力用满 …… **没有更强的教师怎么办：On-Policy 自蒸馏** ——拿上一次更新后的自己作教师，仍能压榨样本效率。

🧭 **归纳**：
- **On-Policy Distillation**：学生按当前策略 rollout，每步用教师对同前文的分布作 soft target——一次 rollout 产生密集监督
- **On-Policy 自蒸馏**：用上次更新后的自己作教师——没有更强教师时仍能压榨样本效率
- 区别于 SFT：保留"在学生当前实际访问的状态上训练"，缓解协变量漂移

## Q7-8 RL 环境造不出怎么办？

- 章节: ch008 §7.9
- 主题: RL 环境

> 📖 **原文** (ch008 §7.9.2)： 但还有一个更根本的问题：很多场景里，高保真环境不是"贵"，而是**根本造不出来**——真实 API 有副作用不能乱调，真实用户不能拿来试错，物理世界更是没法快进。如果连一个可用的"影子世界"都搭不起来，RL 是不是就做不成了？一个越来越主流的思路是：**用模型来模拟环境**——让一个 LLM 扮演环境，生成 Agent 交互所需的反馈。**造不出环境怎么办：让模型扮演环境**。一种实用的替代方案是用强模型模拟环境：对 Agent 输出的动作调用，由另一个 LLM 模拟"如果这是真实环境会返回什么"。成本低、可控性高；缺点是模拟误差会进入训练信号。**但必须指出这条路的风险：模拟器的世界知识就是训练的天花板，模拟器的系统性偏差会被策略照单全收。** 所以工程上的稳妥做法是**混合**：用模型模拟承担大部分交互量，辅以真实环境的交互，并用真实环境交互定期校准模拟器的偏差。

🧭 **归纳**（RL 环境三种来源）：

| 来源 | 真实性 | 成本 | 适用 |
|---|---|---|---|
| **真实环境** | 最高 | 最高 | 仿真器已成熟（游戏/代码） |
| **人造环境** | 中 | 中 | 需业务专家搭建 |
| **模型扮演环境** | 低-中 | 低 | 真实环境造不出时；用强模型模拟"如果是真环境会返回什么" |

**环境/任务分布/评估隔离**——同一组任务不能既做训练又做评估（数据泄漏），必须独立维护训练池和评测池。
