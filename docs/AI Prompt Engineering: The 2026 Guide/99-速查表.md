## 三、4 C's 与公式速查

### 3.1 4 C's 一行版

| C | 含义 | 一问自检 |
|---|---|---|
| **Clear** | What exactly do you want? | 任务类型 + 输出格式 + 受众 + 约束 + 可选示例 都给了吗？ |
| **Concise** | How will you say it? | 删 filler / 合相关子句 / 用直接命令没用 please？ |
| **Contextual** | What does AI need to know? | Role + Situation + Goal + Constraints + Output 都给了吗？ |
| **Conversational** | How should it feel? | 过 Empathy Test：「我会这样跟同事说话吗？」 |

> 一行版：Clear — What exactly do you want? / Concise — How will you say it? / Contextual — What does AI need to know? / Conversational — How should it feel?

### 3.2 Prompt Formula

| 场景 | 公式 |
|---|---|
| **Prompt Formula 简版** | [Task] + [Topic] + [Format/Length] + [Audience] + [Tone/Style] |
| **完整公式** | [Role] + [Situation] + [Task] + [Constraints] + [Format] + [Tone] |

### 3.4 2026 进阶固定套路（App G）

| 套路 | 一句话 |
|---|---|
| **XML-Structured** | `<task>...</task>` `<constraints>...</constraints>` `<notes>...</notes>`，Claude 看得最准 |
| **Extended Thinking** | Reasoning model 内部 CoT；普通模型用 `<scratchpad>...</scratchpad>` 包思考 |
| **Agentic Workflow** | `<role>` + `<tools>` + `<goal>` + `<rules>`，模型自主选工具 |
| **Prompt Caching** | constants 前，variables 后；cacheable prefix 90%+ 折扣 |
| **MCP / Connectors** | 统一接口连 Gmail/GitHub/Slack/Notion/Postgres |
| **Meta-Prompting** | 三模式：writer / critic / optimizer loop |
| **Eval-Driven** | 10-50 输入集 + rubric + LLM-as-judge JSON |
| **Structured Outputs** | API 给 JSON schema，模型必出合规输出 |
| **Long-Context** | 头尾 instructions / section headers / 引用再答 / chunk+summary / 检索替 context |
| **Multimodal** | describe what to look for + structured observations + 迭代 |
| **System/User/Assistant Roles** | 三角色 + prefilling 引导格式（`{` → JSON；`Here is the plan:` → 计划） |
| **Injection Defense** | trusted/untrusted `<tag>` 分开 + Validate output + Least Privilege + Human-in-the-loop |

## 四、模型与温度速查

### 4.1 选哪个模型？

| 需求 | 推荐 |
|---|---|
| 长文档分析 | Claude Sonnet/Opus / Gemini Pro |
| 强推理 / 数学 / 多步逻辑 | Reasoning models（o-series / Opus） |
| 最便宜的高吞吐 | Claude Haiku / Gemini Flash / 高效 GPTs |
| 图像艺术 / 概念艺术 | Midjourney |
| 图像商业+文字入图 | DALL-E / GPT Image / Ideogram |
| 极致摄影 | Google Imagen |
| 本地 / 私有 / 开源 | Llama / Mistral via Ollama / vLLM |
| 视频（文生 / 长时 / 编辑） | Sora / Veo / Runway / Pika / Kling |

### 4.2 温度怎么设？

| 温度 | 用途 |
|---|---|
| 0.0 | 确定性 / 代码 / 事实 Q&A / extraction / 单元测试 |
| 0.3–0.5 | 分析 / 结构化写作（**默认**） |
| 0.7–0.9 | 创意写作 / 头脑风暴 |
| 1.0+ | 实验性 / 失控创意 |

### 4.3 上下文窗口 4 档

| Tokens | 大致等价 |
|---|---|
| 8K | 短章（简单 Q&A） |
| 32K–128K | 中篇 / 短篇集 / 持续对话 |
| 200K | 整本书 / 长代码库 |
| 1M+ | 小型资料库 / 多小时转录 / 整仓 |

## 五、检查清单（Appendix E）

### 5.1 Pre-Prompt Checklist（发之前）
1. Goal（要什么？） 2. Audience（给谁看？） 3. Format（长度/结构/标题/文件类型？） 4. Tone（语气？） 5. Context（要什么背景？） 6. Examples（要示例吗？） 7. Constraints（长度/成本/模型/框架？） 8. Output（纯文本/Markdown/JSON/代码？）

### 5.2 Post-Prompt Checklist（收到后立刻）
1. 达到目标了吗？ 2. 清晰完整吗？ 3. 有事实错误吗？ 4. 有引用幻觉吗？ 5. 一条 refinement prompt 能更好吗？ 6. 要存到 prompt 库吗？

### 5.3 Prompt Library Checklist（入库时）
1. 短名 2. 占位符清单 3. 适用模型 4. 一个期望输出示例 5. 已知失败模式 / 边界条件

### 5.4 Safety & Quality Checklist（对外前）
1. 核对关键事实 2. 无幻觉引用 3. 语气与品牌一致 4. 代码测试通过 5. 无隐私泄漏 6. 拥有商用版权
