# Appendix I: Prompt Engineering Glossary

| Term | Definition |
| Agent | An LLM-based system that autonomously decides when to call tools to achieve a goal. |
| API | Application Programming Interface — the developer-facing endpoint for an LLM. |
| Batch API | A discounted API tier for non-urgent workloads that complete within hours instead of seconds. |
| Chain-of-thought (CoT) | Prompting technique that asks the model to reason step by step before answering. |
| Context window | The maximum number of tokens the model can consider at once. |
| Embedding | A numerical vector representation of text, used for semantic search and RAG. |
| Few-shot prompting | Providing examples inside the prompt so the model imitates them. |
| Fine-tuning | Training a model further on your own data to specialize it. |
| Frontier model | The most capable (and usually most expensive) model from a given provider. |
| Hallucination | When the model generates confident but false information. |
| JSON mode | API feature that constrains the model’s output to valid JSON. |
| LLM | Large Language Model. |
| LoRA | Low-Rank Adaptation — a lightweight fine-tuning method common in image models. |
| MCP | Model Context Protocol — an open standard for connecting LLMs to tools and data. |
| Meta-prompt | A prompt that asks a model to write or improve another prompt. |
| Multimodal | A model that accepts more than one input modality (e.g., text and images). |
| Persona prompting | Instructing the model to act as a specific role or expert. |
| Prompt | The full input given to an AI model. |
| Prompt caching | Reusing a processed prompt prefix across calls to cut cost and latency. |
| Prompt chaining | Passing output from one prompt into another as input. |
| Prompt injection | A security attack where untrusted content embeds malicious instructions into a prompt. |
| RAG | Retrieval-Augmented Generation — inject relevant documents into the prompt at query time. |
| Reasoning model | A model that spends extra compute “thinking” before answering; better at hard problems. |
| Self-consistency | Generating multiple candidate answers and selecting the best. |
| System prompt | The persistent instructions placed before user input. |
| Temperature | A sampling parameter controlling randomness in generation. |
| Token | The unit of text processing for LLMs, typically a few characters. |
| Tool use | A model’s ability to call external functions during a conversation. |
| Top-P | Nucleus sampling parameter — controls which tokens are eligible at each step. |
| Vector database | A database optimized for storing and searching embeddings. |
| Zero-shot prompting | Asking the model to perform a task without providing examples. |
