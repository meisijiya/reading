### RAG 分块（ch16）

| 使用场景 | 推荐块大小 | 重叠 |
|---|---|---|
| 事实型问答（精确事实） | 128–256 Token | 20–32 Token |
| 摘要 / 综合 | 512–1024 Token | 64–128 Token |
| 代码检索 | 完整函数 | 无 |
| 法律 / 监管文档 | 段落级 | 1 句 |
| 对话 / 聊天 | 256–512 Token | 32–64 Token |

出处：ch16 Table 16.3。Embedding 模型上下文窗口**通常为 512 Token**（ch16 §16.2.2）。

### 上下文预算（ch18）

```
C ≥ S + M + T + H + R
    │   │   │   │   └─ reserved（预留输出）
    │   │   │   └───── history（随对话无限增长的那部分）
    │   │   └───────── tool defs（工具定义）
    │   └───────────── memory / RAG
    └───────────────── system prompt
```
出处 ch18 §18.2.1（式 18.1）。**H 会无限扩张而 C 固定**——这是所有上下文工程问题的总根源。

Token 计数警告：「每个 Token 约 4 字符」的经验法则在**代码、JSON、非英文文本**上偏差可达 **20–40%**（ch18 §18.2）。

## 三、常见陷阱（速查）

| 陷阱 | 说明 | 卡 |
|---|---|---|
| **观察泄露** | 基准把真值答案/奖励值/未来步骤放进观察，虚高分数、真实部署灾难性失败 | Q5-11 |
| **reward hacking** | 优化器找到满足 reward 的捷径而非真正目标 | Q4-50 / Q6-3 |
| **Loopmaxxing** | 循环反复重试同一件事，token 烧光 | Q4-50 |
| **Goodhart 定律** | 「当一个度量成为目标时，它就不再是好的度量」 | Q3-24 |
| **上下文静默截断** | 预算超了直接砍掉而非报错，Agent 不知道自己丢了信息 | Q4-32 |
| **工具输出当作可信** | 工具输出必须视为不可信数据，否则提示注入直接生效 | Q4-37 |
| **DPO 长度偏置** | 长度归一化是个需要抉择的问题，不是默认选一个 | Q2-20 |
| **pass@k 不够就先上 RL** | RL 只能放大已存在的行为，不能凭空引入 | Q2-46 / Q2-52 |
| **AutoGen 代码执行高权限** | 生产环境绝不可高权限运行，务必 Docker 隔离 | Q5-47 |
