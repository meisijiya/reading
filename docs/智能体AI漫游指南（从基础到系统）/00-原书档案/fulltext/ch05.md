# Chapter 5 · PPO ——近端策略优化

### 5.1动机与历史

问题：朴素的policy gradient更新对步长没有任何约束。仅仅一次倒霉的batch就可能把policy推入一个生成垃圾文本的区域→垃圾文本获得低reward →下一次gradient让情况更糟→不可挽回地崩溃。解决方案的演进：

1. TRPO [ 317 ]（2015）：对新旧policy之间的KL散度施加约束。效果完美，但需要昂贵的二阶优化（Fisher信息矩阵、共轭梯度）。

2. PPO（2017）[ 319 ]：用一个简单的一阶clipped 目标实现类似的稳定性。实现复杂度低了10 ×，效果几乎一样，且能轻松扩展到分布式训练。

### 5.5 Rollout Buffer与Rollout

在PPO中，数据管理依赖一个被称为Rollout Buffer的专用短期存储系统。与无限期地在replaybuffer中保存经验的离策略算法（如DQN）不同，PPO需要一种短暂存在的结构，以满足其在策略的数学约束。

5.5.1什么是Rollout？

Rollout（轨迹）是Agent在环境中执行当前policy所产生的一段交互序列：

•过程：Agent观察state、选择action、获得reward，然后转移到下一个state。重复进行固定步数，或直到episode结束。

•在大语言模型/RLHF中：一次rollout即从数据集中取出一条prompt，让语言模型一个token接一个token地生成完整序列，直到遇到文本结束标记。每个token就是一个“ step ”。

5.5.2 Rollout Buffer

Rollout buffer临时存储rollout阶段收集到的全部数据。对每个生成的token/step，它记录：

B = { ( s t , a t , log π θ old ( a t | s t ) , r t , V ( s t )) } T(5.13)t =1

• s t , a t , r t：步t的state、所采取的action与reward。

• log π θ old ( a t | s t )：在生成该action的那一个policy下取该action的对数概率（计算ratio时需要）。

• V ( s t )：Value function给出的基线预测（计算GAE advantage时需要）。

5.5.3 Rollout Buffer的生命周期

该buffer按严格的三阶段时钟周期运行：

1.收集：当前policy与环境交互，用新鲜轨迹填满buffer（对一个70B模型，batch=128，max_tokens=512：单次rollout可达65K个token级transition）。

2.训练：对各轨迹计算GAE advantage。使用clipped目标在mini-batch上跑K个epoch（通常3–10）的gradient下降，更新policy权重。

3.清空：整个buffer被彻底清空。由于PPO是on-policy的，旧policy产生的数据无法安全地复用于下一轮更新——比率r t ( θ )会变得过期，clipping保证也会失效。

Rollout Buffer与Replay Buffer的区别

Replay Buffer（DQN、SAC）：Off-policy。无限期地存储数百万条transition。随机采样。数据跨多次更新复用。Rollout Buffer（PPO、GRPO）：On-policy。存储一个batch的轨迹。使用若干epoch后被完全丢弃。每个周期都需要新鲜数据。这就是为什么PPO需要持续生成——每次更新后buffer被清空，需要新的rollout。这也让生成瓶颈（占wall-clock时间60–70%）尤为痛苦。

RLHF场景中的vLLM在RLHF训练中，vLLM被用于生成阶段（占wall-clock 时间60–70%）。Policy 模型生成rollout，随后由reward模型打分。其主要优势：

•批量生成：跨多条prompt并行生成256+条回答。

•显存效率：可容纳更多并发生成→在生成瓶颈期GPU利用率更高。

•前缀共享：当每条prompt生成N = 8条回答时（如GRPO），prompt的KV只算一次并被8条共享——无冗余prefill。

•集成：OpenRLHF、TRL等框架将vLLM作为生成后端，把生成worker（vLLM）与训练worker（DeepSpeed/FSDP）分离。

70B Chat模型的具体PPO步骤

设置：128条prompt一个batch，policy为Llama-3-70B，最大生成512个token。第1步——生成：采样128条回答（temperature=0.7，top-p=0.9）。耗时占60%。第2步——打分：Reward模型对每个(prompt, response)对打分。取值范围：0.2–0.95。第3步—— KL：计算逐token的KL：KL t = log π θ ( y t | y <t ) − log π ref ( y t | y <t )。跨token的均值KL：通常3–8。第4步——最终reward：R = r RM − 0 . 05 × mean_KL（只在最后一个token给）。第5步—— GAE：使用value head 的预测，为每个token 位置计算A ˆ t。对advantage 做whitening（零均值、单位方差）。第6步——更新：在大小为16的mini-batch上跑4个epoch的SGD。Clip比率ϵ = 0 . 2，梯度范数clip至1.0。结果：Policy每步约提升0.005的胜率。10K步后：相对于SFT绝对提升5–10%。

大语言模型RL中的Tokenization陷阱在计算逐token KL惩罚与advantage时，请记住：tokenization决定了什么算一“步”。单个概念性action（例如输出“ 2024 ”）依据tokenizer的不同可能跨越1–4个token。这带来若干微妙问题：

• KL记账：相同的语义内容若被切成不同数量的token，逐token KL加总会得出不同总额（例如，被切成更多子词的稀有词会获得更高的总KL惩罚）。

• Credit分配：GAE按token位置分配advantage ——但语义“决策”常跨越多个token。模型其实只在词首token真正“决定”；后续子词token基本是确定性的。

• Reward放置：只在最后一个token给reward意味着所有先前token必须通过GAE向后回传credit ——越长的回答信号被稀释得越厉害。

缓解措施：一些系统按序列长度对KL做归一化，使用词级reward shaping，或在语义边界（而非最末token）处施加reward。

PPO在内存中维护两份不同的参数状态，它们共享同一神经网络拓扑，但在优化过程中持有不同的权重值：核心架构：两个网络

1. Policy网络（π θ）：由权重θ参数化的、处于活动状态的实时网络。优化过程中通过反向传播持续更新。

2.旧Policy网络（π θ old）：由权重θ old参数化的冻结快照。在单个优化周期内充当静态锚，

防止policy漂移过快。

5.7.1阶段1：Rollout（数据收集）

在数据收集期间，Agent与环境交互T步。在每个时间步t：

1.环境给出当前state/观测s t（对大语言模型而言：prompt +到目前为止已生成的token）。

2. s t被送入当前网络快照（θ old）。

3.网络输出原始未归一化的值—— logits z old ——一个长度为| V |（词表大小32K–128K）的向量。

4.通过Softmax计算概率：

exp( z old ,a )P ( a | s t ) = Softmax( z old ) =(5.14)P | V |j =1 exp( z old ,j )

5.从P ( a | s t )中采样一个action a t（下一个token），并将transition元组⟨ s t , a t , r t , s t +1 ⟩连同log π θ old ( a t | s t )一起存入rollout buffer。

为何要存对数概率？在rollout阶段把log π θ old ( a t | s t )作为标量保存，可以避免在优化期间重新运行冻结的网络。每个mini-batch因此可省下一次完整forward pass ——对70B模型而言意义重大。

5.7.2阶段2：优化循环（Mini-Batch更新）

一旦rollout buffer填满，PPO就在mini-batch上跑K个epoch（通常3–10）。在每个gradient步中，使用所存state s t为两个policy同时生成logits：旧Policy评估（冻结）：

z old = f ( s t ; θ old ) −→ log π θ old ( a t | s t ) = LogSoftmax( z old )[ a t ] (5.15)

实现捷径：复用rollout时保存的标量，而非重新计算。实时Policy评估（更新中）：

z new = f ( s t ; θ ) −→ log π θ ( a t | s t ) = LogSoftmax( z new )[ a t ] (5.16)

由于每次mini-batch gradient步后θ都会更新，z new会在整个优化循环中持续变化，而z old则始终保持不变。

5.7.3从Logits到概率比

PPO的核心比率衡量某个action在新policy下相对旧policy的概率变化：

π θ ( a t | s t )(5.17)r t ( θ ) =π θ old ( a t | s t )

为了避免直接除原始概率带来的数值下溢/上溢灾难，计算在对数空间中进行：

log π θ ( a t | s t ) = LogSoftmax( z new )[ a t ] (5.18)log π θ old ( a t | s t ) = LogSoftmax( z old )[ a t ] (5.19)

比率由差值的指数恢复：

r t ( θ ) = exp(log π θ ( a t | s t ) − log π θ old ( a t | s t )) (5.20)

该比率随后被代入PPO的clipping目标：hiL CLIP ( θ ) = E ˆ tr t ( θ ) A ˆ t , clip( r t ( θ ) , 1 − ϵ, 1+ ϵ ) A ˆ t(5.21)min

Clipping的工作方式

•若A ˆ t > 0（好action）：比率被clip至1 + ϵ ——不会对好action过度利用。

•若A ˆ t < 0（坏action）：比率被clip至1 − ϵ ——不会对坏action过度惩罚。

• min( · )保证我们始终取更保守的估计。

结果：在一个信任域内实现单调改进——不会出现灾难性崩溃。
