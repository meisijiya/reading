## Q2-1 第 4 章「大语言模型的强化学习基础」解决了什么问题？

- 章节: ch04　（原文：[ch04](../00-原书档案/fulltext/ch04.md)）
- 主题: 为什么要对 LLM 做强化学习

> 📖 **原文** (ch04)：监督微调（Supervised Fine-Tuning, SFT）教模型模仿示例，但模仿存在天花板：模型永远无法超越其训练数据的质量。强化学习突破了这一壁垒。通过生成新文本、接收reward反馈，并朝着获得更高reward的行为更新，经过RL训练的模型能够发现任何人类示范者都未曾写出的策略——产出更有帮助、更准确、且更契合人类偏好的输出

> 📖 **原文** (ch04)：这是每一款前沿模型背后的机制：GPT-4 [ 274 ]、Claude、Llama-3 [ 118 ]和DeepSeek-R1 [ 72 ]都在SFT之后施加RL，作为把一个能力强但缺乏导向的模型转化为对齐助手的关键一步。

🧭 **归纳**：本章给出后续 7 章的公共地基，关键结论有四条。

| 结论 | 内容 |
|---|---|
| 为什么是 RL | 模仿有质量天花板，RL 能靠 reward 探索出示范数据里不存在的策略 |
| 落地位置 | SFT 之后的「定向」阶段，是把通用能力模型变成对齐助手的必经一步 |
| 建模方式 | 自回归生成 = 一个 Markov 决策过程（MDP），见 Q2-3 |
| 与经典 RL 的分野 | 确定性转移、稀疏 reward、巨大动作空间、KL 锚、无需 value function —— 这决定了 PPO/GRPO 而非 DQN 成为主流 |

➕ **补充**：本章把「RL 超越数据天花板」作为动机，落到工程上其实是「reward 可验证性」决定了能走多远：能写判分器的任务（数学、代码、工具执行）才能真正享受这个红利，这一点在本部分后续章节里会反复出现。

## Q2-2 大语言模型的 RL 分成哪两大范式？

- 章节: ch04 §4.1　（原文：[ch04](../00-原书档案/fulltext/ch04.md)）
- 主题: 对齐范式与可验证奖励范式

> 📖 **原文** (ch04 §4.1)：基于人类反馈的强化学习（Reinforcement Learning fromHuman Feedback, RLHF）[ 57 , 280 , 442 ]利用人类两两比较的判断（“哪个回答更好？”）来训练reward模型，然后优化policy以最大化这一学到的reward。

> 📖 **原文** (ch04 §4.1)：DeepSeek-R1 [ 72 ] 证明，配合基于规则的reward（格式正确性+答案准确性）的GRPO能够在完全不使用人类偏好数据的情况下，训练模型发展出复杂的思维链（Chain-of-Thought，CoT）推理。

> 📖 **原文** (ch04 §4.1)：这一范式——可验证奖励的强化学习（ReinforcementLearning from Verifiable Rewards, RLVR）——如今已成为构建推理模型和agentic 系统的主流路线。

🧭 **归纳**：

| | 范式一：RLHF / DPO | 范式二：RLVR |
|---|---|---|
| 目标 | 对齐——让模型有帮助、无害且诚实 | 教授新能力——推理、数学、代码生成 |
| reward 来源 | 人类两两比较训练出的 reward 模型 | 可验证结果：答案是否正确、代码是否通过测试 |
| 是否需要偏好数据 | 需要 | 不需要 |
| 代表 | GPT-4、Claude | DeepSeek-R1 |

两种方法都能产出能够遵循指令且尊重安全约束的对齐助手——这是范式一的目标；范式二则是当前构建推理模型与 agentic 系统的主流路线。

➕ **补充**：两个范式不是互斥的，实践中常常串联：先用 RLHF 定行为，再用 RLVR 灌能力。区别在于 reward 的来源是否可自动判定，这一判定直接决定数据能不能规模化和能不能做环境交互。

**但两类范式共享同一套底层组件**：

> 📖 **原文** (ch04 §4.1)：尽管两类范式的目标不同，但它们共享同一套核心机制：

> 📖 **原文** (ch04 §4.1)：•一个reward信号r ( x, y )（来自偏好学习或来自验证计算）

> 📖 **原文** (ch04 §4.1)：•相对于参考policy的KL约束，用于防止退化解

> 📖 **原文** (ch04 §4.1)：•用于将模型朝更高reward方向更新的policy gradient优化（PPO或GRPO）

🧭 **归纳**：四个共享组件（据原文列表整理）——本部分后续 7 章就是逐一展开这四个组件的细节。

1. **policy** π θ：一个自回归生成文本的大语言模型本身。
2. **reward 信号** r(x, y)：要么来自偏好学习，要么来自验证计算。
3. **KL 约束**：相对 reference policy，防止退化解。
4. **policy gradient 优化器**：PPO 或 GRPO，负责把模型往高 reward 方向推。

本部分后续章节就是逐一展开这四个组件的细节。

## Q2-3 文本生成是怎样被建模成一个 MDP 的？

- 章节: ch04 §4.2　（原文：[ch04](../00-原书档案/fulltext/ch04.md)）
- 主题: LLM 即 Agent 的 MDP 映射

> 📖 **原文** (ch04 §4.2)：让RL得以应用于语言模型的关键洞察，是将自回归生成重述为一个Markov决策过程（MDP）：

> 📖 **原文** (ch04 §4.2)：把大语言模型想象成一个Agent，正在一个token接一个token地撰写回答。在每一步，它查看到目前为止写下的全部内容（state）、选择下一个词（action），页面随之增长一个token（transition）。当回答完成时，一位评判者对其打分（reward）。目标是：学到一种持续获得高分的写作策略（policy）。

> 📖 **原文** (ch04 §4.2)：这种映射之所以强大，是因为大语言模型本身就已经是一个policy ——其Softmax输出为每一个state定义了π θ ( a t | s t )。我们无需另行构建一个policy网络；只需调整权重θ，让模型为能获得更高reward的token序列赋予更高概率。

🧭 **归纳**：MDP 六元组在语言生成上的对应（据原文定义整理）：

| MDP 元素 | 文本生成中的含义 |
|---|---|
| State | prompt 与已生成 token 的拼接 |
| Action | 从词表中选下一个 token（32K–128K 选一） |
| Transition | 确定性的，只是追加 token，环境无随机性 |
| Reward | 通常只在生成结束时给出（稀疏）；RLHF 是 reward 模型评分，RLVR 是答案正确性 |
| Policy | 大语言模型本身的下一 token 概率分布 |
| 折扣因子 | γ = 1.0，episode 是一条完整回答，不折扣 |

➕ **补充**：正因为 LLM 已经天然满足 policy 的定义，RLHF 才不需要额外训一个 actor 网络；PPO 里的「actor」就是被微调的语言模型本身，额外开销来自 reference / reward / critic 三份副本。

## Q2-4 经典 RLHF 流水线有哪四个阶段？RLVR 如何替换其中一部分？

- 章节: ch04 §4.3　（原文：[ch04](../00-原书档案/fulltext/ch04.md)）
- 主题: RLHF 四阶段与 RLVR 变体

> 📖 **原文** (ch04 §4.3)：1.监督微调（SFT）：在高质量示例上训练base模型，得到一个能够遵循指令的policy π SFT。

> 📖 **原文** (ch04 §4.3)：3. RL优化：以reward模型作为信号，通过PPO或GRPO优化policy，并对π SFT施加KL约束。

> 📖 **原文** (ch04 §4.3)：对于RLVR（推理/agentic训练），阶段1–2被替换：SFT模型在推理轨迹上训练，reward模型被替换为验证器（例如检查数学正确性）。阶段3不变——使用PPO或GRPO针对reward信号进行优化。

🧭 **归纳**：四阶段流水线（据原文整理）：

1. **SFT**：在高质量示例上训出可遵循指令的 policy π SFT。
2. **Reward 模型训练**：收集人类偏好比较，用 Bradley-Terry 目标训 reward 模型。
3. **RL 优化**：以 reward 为信号，用 PPO 或 GRPO 优化 policy，并对 π SFT 施加 KL 约束。
4. **评估与迭代**：评估对齐后的模型，收集新失败案例，再迭代。

RLVR 的改动集中在前两阶段（数据换成推理轨迹、reward 模型换成验证器），第三阶段完全复用——这就是为什么 RLVR 落地成本比 RLHF 低得多。

## Q2-5 LLM 场景下的 RL 和经典 RL 有哪些关键差异？

- 章节: ch04 §4.3　（原文：[ch04](../00-原书档案/fulltext/ch04.md)）
- 主题: LLM RL 的五个特殊之处

> 📖 **原文** (ch04 §4.3)：•确定性transition：所谓“下一个state ”只是先前token的拼接——没有随机环境。

> 📖 **原文** (ch04 §4.3)：• KL锚：LLM RL被约束保持在SFT policy附近，以防止reward hacking，代价是探索受限。

> 📖 **原文** (ch04 §4.3)：•无需value function：GRPO完全去掉了critic网络，转而采用reward的组相对归一化。

> 📖 **原文** (ch04 §4.3)：这些差异解释了为何在大语言模型上PPO与GRPO占据主导，而非DQN式方法。

🧭 **归纳**：五条差异（据原文列表整理）：

| 差异 | 说明 | 后果 |
|---|---|---|
| 确定性 transition | 下一个 state 只是 token 拼接 | 无需环境模拟器 |
| 稀疏 reward | 结果 reward 只在结束时给一次，或关键步骤给过程 reward | credit 分配困难 |
| 巨大动作空间 | 每步 32K–128K 候选 token，探索靠温度采样隐式完成 | 探索效率受限 |
| KL 锚 | 被约束在 SFT policy 附近 | 防 reward hacking，代价是探索受限 |
| 无需 value function | GRPO 去掉 critic，用组相对归一化 | 省一份大模型 |

➕ **补充**：这五条差异也解释了为什么「经典 RL 的经验回放 + 价值网络」这套组合在 LLM 上不划算——确定性转移让环境模拟失去意义，动作空间太大让经验回放的样本效率极低，而稀疏 reward 又让价值估计变得不可靠。

## Q2-7 第 5 章「PPO」解决了什么问题？

- 章节: ch05　（原文：[ch05](../00-原书档案/fulltext/ch05.md)）
- 主题: PPO 的动机与历史

> 📖 **原文** (ch05)：问题：朴素的policy gradient更新对步长没有任何约束。仅仅一次倒霉的batch就可能把policy推入一个生成垃圾文本的区域→垃圾文本获得低reward →下一次gradient让情况更糟→不可挽回地崩溃。解决方案的演进：

> 📖 **原文** (ch05 §5.1)：1. TRPO [ 317 ]（2015）：对新旧policy之间的KL散度施加约束。效果完美，但需要昂贵的二阶优化（Fisher信息矩阵、共轭梯度）。

> 📖 **原文** (ch05 §5.1)：2. PPO（2017）[ 319 ]：用一个简单的一阶clipped 目标实现类似的稳定性。实现复杂度低了10 ×，效果几乎一样，且能轻松扩展到分布式训练。

🧭 **归纳**：本章关键结论清单：

1. **要解决的问题**：朴素 policy gradient 对步长无约束，一个坏 batch 就能让 policy 不可挽回地崩溃。
2. **PPO 的取舍**：用一阶 clipped 目标换取接近 TRPO 的稳定性，实现复杂度降低 10 倍，且容易扩展到分布式训练。
3. **代价**：PPO 需要 critic 网络（value function），显存翻倍、且 critic 训不准时会污染 advantage——这正是 GRPO 要删掉的东西。
4. **本章还覆盖**：完整 loss 的三项组成、从 RL 目标到更新规则的六步推导、rollout buffer 生命周期、端到端训练循环、超参取值。

➕ **补充**：PPO 的稳定性来自「悲观下界」——它在数学上等价于给更新幅度设了一个软约束，这是它能替代 TRPO 硬 KL 约束的根本原因，后面 Q2-10 的推导会具体展开。

## Q2-8 PPO 的 clipped surrogate 目标是什么？min 算子在起什么作用？

- 章节: ch05 §5.2　（原文：[ch05](../00-原书档案/fulltext/ch05.md)）
- 主题: clipped 目标与悲观下界

> 📖 **原文** (ch05 §5.2)：PPO的核心创新是一个clipped surrogate目标：它能阻止破坏性的大幅policy更新，同时保持实现简单。

> 📖 **原文** (ch05 §5.2)：min算子构造了一个悲观下界：

> 📖 **原文** (ch05 §5.2)：•好的action（A > ˆ 0）：我们希望提升其概率。Surrogate r A ˆ会随r增大而增大，但clip将收益上限锁在r = 1 + ϵ。“别因为一个好例子就贪心。”

> 📖 **原文** (ch05 §5.2)：•坏的action（A < ˆ 0）：我们希望降低其概率。r A ˆ会随r减小而改善，但clip将收益上限锁在r = 1 − ϵ。“别因为一个坏例子就遗忘得太激进。”

> 📖 **原文** (ch05 §5.2)：净效应：每次更新步中policy的变化最多在± 20%之内，既能防止灾难性崩溃，也能防止过度自信地走向特化。

🧭 **归纳**（据原文公式 5.1 整理，符号保留原书命名）：

$$L^{CLIP}(\theta) = \mathbb{E}_t\Big[\min\big(r_t(\theta)\hat{A}_t,\ \mathrm{clip}(r_t(\theta), 1-\epsilon, 1+\epsilon)\hat{A}_t\big)\Big]$$

其中概率比 $r_t(\theta) = \pi_\theta / \pi_{\theta_{old}}$。

- 对**好动作**（Â > 0）：clip 把收益上限锁在 r = 1 + ε——「别因为一个好例子就贪心」。
- 对**坏动作**（Â < 0）：clip 把收益上限锁在 r = 1 − ε——「别因为一个坏例子就遗忘得太激进」。
- min 算子保证在 (clipped, unclipped) 两项里永远取更保守的那个，等价于对改进设了一个悲观下界。

➕ **补充**：ε = 0.2 对应每次更新最多 ±20% 的概率变化，这是 PPO 最常被引用的一条经验常数（原文 §5.9 的 cliprange 典型值同为 0.2）。

## Q2-9 完整的 PPO loss 由哪几项组成？系数怎么取？

- 章节: ch05 §5.3　（原文：[ch05](../00-原书档案/fulltext/ch05.md)）
- 主题: PPO 三项损失

> 📖 **原文** (ch05 §5.3)：•Value loss（c 1 = 0 . 1）：训练critic去预测return；同样被clip以保持稳定。

> 📖 **原文** (ch05 §5.3)：•熵奖励（c 2 = 0 . 01）：防止过早收敛到确定性policy，对探索至关重要。

🧭 **归纳**（据原文公式 5.2 整理）：

$$L = L^{CLIP} - c_1\big(V_\theta(s_t) - V_{target}\big)^2 + c_2 H[\pi_\theta(\cdot|s_t)]$$

| 分项 | 作用 | 系数（原文取值） |
|---|---|---|
| clipped policy loss | 限制策略更新幅度 | 主项 |
| value loss | 训 critic 预测 return，同样被 clip 保稳定 | c₁ = 0.1 |
| entropy bonus | 防止过早收敛到确定性 policy，对探索至关重要 | c₂ = 0.01 |

熵奖励这一项常被忽略，但它是 PPO 保持探索能力的唯一显式来源——去掉它，策略很容易在早期就坍塌到少数几条高 reward 轨迹上（这一点与 Q2-27 的多样性坍塌是同一现象的两面）。

## Q2-10 从 RL 目标到 PPO 更新规则的推导链条是什么？

- 章节: ch05 §5.4　（原文：[ch05](../00-原书档案/fulltext/ch05.md)）
- 主题: PPO 六步推导与有效性来源

> 📖 **原文** (ch05 §5.4.4)：L CPI是一个合法的目标，但若无约束，单次gradient步就可能让r t ( θ )远离1.0，导致：

> 📖 **原文** (ch05 §5.4.4)：•重要性权重变得极端→方差升高

> 📖 **原文** (ch05 §5.4.4)：•灾难性崩溃：policy生成垃圾，且无法恢复

> 📖 **原文** (ch05 §5.4.5)：PPO用一个clipped目标取代硬性KL约束，仅使用一阶gradient即可达到类似行为：

> 📖 **原文** (ch05 §5.4.6)：小结：它为何有效1. Policy gradient定理给出了改进policy的方向。

> 📖 **原文** (ch05 §5.4.6)：5.结果：以概率1实现单调改进，且只用一阶gradient。无需Hessian、共轭梯度或线搜索。

🧭 **归纳**：原文 §5.4 的六步路径：

1. RL 目标：最大化期望累计 reward。
2. Policy Gradient 定理：用优势函数替代完整 return 以降低方差。
3. 离策略数据的重要性采样：PPO 用 π_old 收数据、π 更新，需修正分布失配。
4. 无约束 surrogate 的问题：重要性权重变极端 → 方差升高、policy 进入未验证区域、灾难性崩溃；TRPO 用 KL 硬约束解决，但需二阶方法。
5. PPO 的 clipped surrogate（一阶近似）：用 clip 取代硬 KL 约束，梯度在越界时为 0。
6. 完整更新规则：clipped policy loss + value loss + 熵奖励组合。

**它为何有效**（原文小结）：① policy gradient 定理给出改进方向；② 重要性采样让 π_old 的数据可跨多个 epoch 复用；③ clipping 防止重要性权重变极端；④ min 算子始终取更保守项；⑤ 结果是以一阶梯度实现单调改进，无需 Hessian、共轭梯度或线搜索。

➕ **补充**：第 4 步给出的失效链条是整个 PPO 的设计动机——「重要性权重极端」与「进入未验证区域」这两条直接对应了 Q2-11 里 rollout buffer 必须每轮清空的硬性规定。

## Q2-11 Rollout Buffer 的生命周期是怎样的？为什么 PPO 不能用 Replay Buffer？

- 章节: ch05 §5.5　（原文：[ch05](../00-原书档案/fulltext/ch05.md)）
- 主题: Rollout Buffer 三阶段与 Replay 对比

> 📖 **原文** (ch05 §5.5)：在PPO中，数据管理依赖一个被称为Rollout Buffer的专用短期存储系统。与无限期地在replaybuffer中保存经验的离策略算法（如DQN）不同，PPO需要一种短暂存在的结构，以满足其在策略的数学约束。

> 📖 **原文** (ch05 §5.5.3)：1.收集：当前policy与环境交互，用新鲜轨迹填满buffer（对一个70B模型，batch=128，max_tokens=512：单次rollout可达65K个token级transition）。

> 📖 **原文** (ch05 §5.5.3)：3.清空：整个buffer被彻底清空。由于PPO是on-policy的，旧policy产生的数据无法安全地复用于下一轮更新——比率r t ( θ )会变得过期，clipping保证也会失效。

> 📖 **原文** (ch05 §5.5)：Replay Buffer（DQN、SAC）：Off-policy。无限期地存储数百万条transition。随机采样。数据跨多次更新复用。Rollout Buffer（PPO、GRPO）：On-policy。存储一个batch的轨迹。使用若干epoch后被完全丢弃。每个周期都需要新鲜数据。

🧭 **归纳**：三阶段时钟周期（据原文整理）：

| 阶段 | 动作 | 说明 |
|---|---|---|
| 收集 | 当前 policy 与环境交互填满 buffer | 70B / batch=128 / max_tokens=512 时，单次 rollout 可达 65K 个 token 级 transition |
| 训练 | 算 GAE advantage，clipped 目标跑 K 个 epoch（通常 3–10） | 数据在多个 epoch 内复用 |
| 清空 | 整个 buffer 丢弃 | 旧 policy 的数据会让比率 r_t(θ) 过期、clipping 失效 |

**Rollout Buffer vs Replay Buffer**：

| | Replay Buffer（DQN、SAC） | Rollout Buffer（PPO、GRPO） |
|---|---|---|
| 范式 | Off-policy | On-policy |
| 容量 | 无限期存数百万条 transition | 只存一个 batch 的轨迹 |
| 采样 | 随机采样 | 整批用若干 epoch 后全丢 |
| 复用 | 数据跨多次更新复用 | 每个周期都需新鲜数据 |

这也是为什么 PPO 必须持续生成：每次更新后 buffer 被清空，需要新的 rollout，生成瓶颈（占 wall-clock 时间 60–70%）因此尤为痛苦。

## Q2-12 一个 70B chat 模型的 PPO 训练循环具体长什么样？

- 章节: ch05 §5.6　（原文：[ch05](../00-原书档案/fulltext/ch05.md)）
- 主题: PPO 六步与关键超参

> 📖 **原文** (ch05 §5.6)：设置：128条prompt一个batch，policy为Llama-3-70B，最大生成512个token。

> 📖 **原文** (ch05 §5.6)：第3步—— KL：计算逐token的KL：KL t = log π θ ( y t | y <t ) − log π ref ( y t | y <t )。跨token的均值KL：通常3–8。

> 📖 **原文** (ch05 §5.6)：第4步——最终reward：R = r RM − 0 . 05 × mean_KL（只在最后一个token给）。

> 📖 **原文** (ch05 §5.6)：结果：Policy每步约提升0.005的胜率。10K步后：相对于SFT绝对提升5–10%。

🧭 **归纳**：原文给出的六步与取值：

| 步骤 | 内容 | 取值 |
|---|---|---|
| 1 生成 | 采样 128 条回答，耗时占 60% | temperature=0.7，top-p=0.9，最大 512 token |
| 2 打分 | reward 模型对每个 (prompt, response) 打分 | 取值范围 0.2–0.95 |
| 3 KL | 逐 token 计算与 reference 的 KL | 跨 token 均值 KL 通常 3–8 |
| 4 最终 reward | reward 模型分减去 KL 惩罚，只在最后一个 token 给 | R = r_RM − 0.05 × mean_KL |
| 5 GAE | 用 value head 预测算每个位置的 advantage，做 whitening | 零均值、单位方差 |
| 6 更新 | mini-batch 上跑 4 个 epoch 的 SGD | mini-batch=16，clip 比率 ε=0.2，梯度范数 clip 至 1.0 |

另见 §5.9 关键超参表：`cliprange` 0.2、`init_kl_coef` 0.01–0.1、`target_kl` 4–8、`ppo_epochs` 4、`learning_rate` 1–5 × 10⁻⁶、`batch_size` 64–256、`temperature` 0.7–1.0。

## Q2-13 Tokenization 给逐 token 的 KL 与 credit 分配带来哪些陷阱？

- 章节: ch05 §5.6　（原文：[ch05](../00-原书档案/fulltext/ch05.md)）
- 主题: tokenizer 造成的记账偏差

> 📖 **原文** (ch05 §5.6)：在计算逐token KL惩罚与advantage时，请记住：tokenization决定了什么算一“步”。单个概念性action（例如输出“ 2024 ”）依据tokenizer的不同可能跨越1–4个token。

> 📖 **原文** (ch05 §5.6)：• KL记账：相同的语义内容若被切成不同数量的token，逐token KL加总会得出不同总额（例如，被切成更多子词的稀有词会获得更高的总KL惩罚）。

> 📖 **原文** (ch05 §5.6)：• Reward放置：只在最后一个token给reward意味着所有先前token必须通过GAE向后回传credit ——越长的回答信号被稀释得越厉害。

> 📖 **原文** (ch05 §5.6)：缓解措施：一些系统按序列长度对KL做归一化，使用词级reward shaping，或在语义边界（而非最末token）处施加reward。

🧭 **归纳**：三个微妙问题（据原文列表整理）：

1. **KL 记账**：同一语义被切成不同数量的 token，逐 token 求和结果就不同——稀有词因切成更多子词而获得更高总 KL 惩罚。
2. **Credit 分配**：GAE 按 token 位置分 advantage，但语义决策常跨多个 token；模型其实只在词首 token 真正「决定」，后续子词 token 基本是确定性的。
3. **Reward 放置**：只在最后一个 token 给 reward，前面所有 token 靠 GAE 向后回传，回答越长信号被稀释得越厉害。

对应三种缓解手段：按序列长度归一化 KL、词级 reward shaping、在语义边界而非最末 token 处施加 reward。

## Q2-16 DPO 的 loss 是怎么推出来的？隐式 reward 是什么？

- 章节: ch06 §6.2　（原文：[ch06](../00-原书档案/fulltext/ch06.md)）
- 主题: DPO 的四步推导

> 📖 **原文** (ch06 §6.2)：第4步：代入Bradley-Terry偏好模型P ( y w ≻ y l ) = σ ( r ( y w ) − r ( y l ))。Z ( x )项相互抵消！

> 📖 **原文** (ch06 §6.2)：DPO在最小化一个交叉熵loss，其中“标签”是：被选回答的隐式reward应高于被拒回答。

🧭 **归纳**：原文的四步推导（据 §6.2 整理）：

1. **RLHF 目标**：最大化期望 reward，同时减去 β 倍的 KL 惩罚。
2. **最优解**：该目标下的最优 policy 有闭式解，形如 π_ref 乘一个由 reward 决定的归一化因子。
3. **重排**：用 policy 把 reward 反解出来——reward 就是 policy 与 reference 的对数概率差，再加一个只依赖 prompt 的项。
4. **代入 Bradley-Terry**：reward 差中的公共项（原文记作 Z(x)）相互抵消，剩下的就是 DPO loss。

结论：DPO 实际在最小化的，是一个「被选回答的隐式 reward 要高于被拒回答」的二元交叉熵；隐式 reward 就是 policy 与 reference 的对数概率差乘以 β。

➕ **补充**：这套推导是整个偏好优化家族的公共母式——后面 f-DPO、Robust DPO、TR-DPO、EXO、NCA、SimPO 全都只是在改 loss 的形状、β 的行为或 reference 的更新方式，而不是改目标。

## Q2-18 DPO 的梯度分析说明了模型在学什么？

- 章节: ch06 §6.3 + ch06 §6.5.4　（原文：[ch06](../00-原书档案/fulltext/ch06.md)）
- 主题: 梯度分解与自适应学习率

> 📖 **原文** (ch06 §6.3)：解读：Gradient会提升“被选”项的概率，降低“被拒”项的概率。当模型当前更偏好错误答案时，权重最大——也就是说，它把学习重点放在“易混淆”的成对样本上。

> 📖 **原文** (ch06 §6.5.4)：关键洞察：缩放因子σ ( − β · h θ )在两条序列的所有token间共享，相当于一个自适应学习率：

> 📖 **原文** (ch06 §6.5.4)：•当h θ较小（模型分不清被选与被拒）：缩放≈ 0 . 5 —— gradient强，激进地学。

> 📖 **原文** (ch06 §6.5.4)：•当h θ较大（模型已经偏好被选）：缩放≈ 0 —— gradient可忽略，避免过拟合。

> 📖 **原文** (ch06 §6.5.4)：相对reference：只有相对π ref的差值才重要。如果模型本就给被选回答高概率（与reference一致），那么gradient就几乎为零。

🧭 **归纳**：两条梯度层面的结论：

**1. 序列级（§6.3）**：梯度整体方向是「提升被选、压低被拒」，但乘上一个权重因子——模型当前越搞错方向（越偏好被拒），权重越大。所以 DPO 把学习重点自动放在**易混淆的成对样本**上，而不是已经学会的样本上。

**2. Token 级（§6.5.4）**：所有 token 共享同一个缩放因子 σ(−β·h)，等效于一个自适应学习率——margin 小（模型分不清）时缩放≈0.5、梯度强；margin 大（模型已偏好被选）时缩放≈0、梯度可忽略。并且只有**相对 reference 的差值**才重要：若模型本来就给被选高概率，梯度几乎为零。

➕ **补充**：这也是 DPO 「不会像 PPO 那样对大量样本平均」的原因——它天然把算力集中在难样本上，但也因此更容易记住单个噪声样本对（见 Q2-22 第 4 点）。

## Q2-19 DPO 训练中哪些 token 会收到梯度？

- 章节: ch06 §6.5.6　（原文：[ch06](../00-原书档案/fulltext/ch06.md)）
- 主题: DPO 的标签掩码规则

> 📖 **原文** (ch06 §6.5.1)：关键细节：Gradient会流过y w和y l中的每一个token位置。中间token不做掩码——每个token都对序列级对数概率有贡献。

> 📖 **原文** (ch06 §6.5.6)：• Prompt token（x）：无gradient。Loss仅在回答位置上计算。Prompt token提供上下文，但其logits不参与log π ( y | x )。

## Q2-20 长度归一化在 DPO 里为什么是个需要抉择的问题？

- 章节: ch06 §6.5.5　（原文：[ch06](../00-原书档案/fulltext/ch06.md)）
- 主题: 序列级求和 vs 长度归一化

> 📖 **原文** (ch06 §6.5.5)：一个微妙问题：越长的序列对数概率天然越低（求和的项更多，且每项≤ 0）。若| y w | ≫| y l |，loss会偏向于偏好更短的回答。

> 📖 **原文** (ch06 §6.5.5)：•标准DPO：使用原始求和（不归一化）。这会隐式惩罚冗长——模型必须对被选回答中的每个token都赋予高概率。

> 📖 **原文** (ch06 §6.5.5)：•实际影响：在benchmark上，长度归一化的DPO能减少长度博弈，但可能损害指令遵循质量。生产中更常用未归一化的标准版本。

🧭 **归纳**：

- **问题根源**：序列对数概率是逐 token 求和，长序列天然更低，所以未归一化的 loss 会偏向更短的回答。
- **标准 DPO**：用原始求和，**隐式惩罚冗长**——模型必须对被选回答的每一个 token 都赋高概率。好处是训练信号覆盖了整段回答。
- **长度归一化 DPO**：把序列对数概率换成平均对数概率（原文明示 SimPO 走这条路）。能减少长度博弈，但可能损害指令遵循质量。
- **生产结论**：更常用未归一化的标准版本。

➕ **补充**：原文给出的两条实现陷阱与此直接相关——「忘记屏蔽 prompt」会让模型去优化 prompt 的似然；「用均值替代求和」会改变隐式长度惩罚，两者都会让有效 β 的行为偏离预期。

## Q2-21 DPO 的 batch size 怎么定？显存还能怎么省？

|---|---|---|
| 分布漂移 | 在与当前 policy 无关的分布上优化 | Online DPO（Q2-34）、KTO、ORPO |

| Reference 崩塌 | 太强则 policy 动不了，太弱则失去正则 | 调 β、用 LoRA（免 reference）、SimPO / ORPO |

## Q2-24 第 7 章「GRPO」解决了什么问题？

- 章节: ch07　（原文：[ch07](../00-原书档案/fulltext/ch07.md)）
- 主题: GRPO 的核心思想与适用场景

> 📖 **原文** (ch07)：组相对策略优化（Group Relative Policy Optimization, GRPO）[ 323 ] 是一种专为语言模型设计的强化学习算法，它消除了对独立value network（critic）的需求。

> 📖 **原文** (ch07)：其核心思想看似简单却出人意料地有效：与其训练一个神经网络去预测期望reward（即PPO中的critic），GRPO通过对同一prompt生成多条响应、利用该组的reward统计量作为baseline，从经验上估计这一基线。

> 📖 **原文** (ch07)：而且——令人意外的是——往往优于PPO，因为经验基线比训练不充分的value function更准确。

> 📖 **原文** (ch07 §7.2)：DeepSeek-R1突破[ 72 ]：纯GRPO配合二值正确性reward（答对r = 1，答错r = 0）在数学/代码上训练时，模型自发涌现出思维链（Chain-of-Thought，CoT）推理、自我验证和错误纠正——完全没有被显式指示这么做。

🧭 **归纳**：

| 收益 | 说明 |
|---|---|
| 去掉 critic | 显存里少一整个模型，工程复杂度减半 |
| 效果反而更好 | 经验基线比训练不充分的 value function 更准确 |
| 默认算法 | 被大多数开源对齐框架（TRL、OpenRLHF、veRL）作为默认算法采用 |

原文点名的三个适用场景：可验证 reward 的推理任务（数学、代码，二值正确性提供干净信号）、70B 及以上大模型（去 critic 的显存节省至关重要）、多轮对话与 Agent 场景（跨工具调用的价值估计本就难以处理）。

## Q2-25 PPO 的 critic 有哪三大问题？GRPO 用组统计量怎么替代它？

- 章节: ch07 §7.1 + ch07 §7.2　（原文：[ch07](../00-原书档案/fulltext/ch07.md)）
- 主题: 去 critic 的动机与组归一化

> 📖 **原文** (ch07 §7.1)：1.显存：value head与policy共享主干（70B模型占140GB）。若分离则显存翻倍。

> 📖 **原文** (ch07 §7.1)：2.精度：对部分序列预测期望reward极其困难。value function经常出错→ advantage出错→gradient方向出错。

> 📖 **原文** (ch07 §7.1)：3.训练：value head需要大量样本才能收敛。RL早期它给出嘈杂的预测，破坏policy学习的稳定性。

> 📖 **原文** (ch07 §7.1)：GRPO的关键洞见[ 323 ]：与其学习V ( s )，不如从一组样本中经验地估计它。对同一prompt生成G条响应，计算它们的reward，并用组统计量作为baseline。

> 📖 **原文** (ch07 §7.2)：组均值近似V ( s )：若对同一prompt采样足够多的响应，其平均reward就是期望reward的蒙特卡洛估计，即value function。高于均值=好动作：A ˆ i > 0表示该响应对该prompt比平均更好，应强化。低于均值=坏动作：A ˆ i < 0表示比平均更差，应抑制。

> 📖 **原文** (ch07 §7.2)：归一化：除以σ G确保advantage在不同reward量级的prompt之间具有尺度不变性。

🧭 **归纳**（据原文公式 7.1 整理）：算法四步为——① 对每个 prompt 采样 G 条 completion；② 逐条算 reward；③ 组内归一化得 advantage；④ 用这些 advantage 做 PPO 风格的 clipped 更新，并加 KL 惩罚。

**为什么组归一化有效**：

- **组均值 ≈ V(s)**：同一 prompt 采足够多响应时，平均 reward 就是期望 reward 的蒙特卡洛估计，也就是 value function。高于均值=好动作（强化），低于均值=坏动作（抑制）。
- **除以组内标准差**：保证 advantage 在不同 reward 量级的 prompt 之间具有尺度不变性——否则简单题和难题的 advantage 量级会差好几个数量级。

## Q2-26 GRPO 的组大小怎么选？什么叫 Goldilocks 原则？

- 章节: ch07 §7.4　（原文：[ch07](../00-原书档案/fulltext/ch07.md)）
- 主题: 组大小与难度匹配

> 📖 **原文** (ch07 §7.4)：关键：组内必须同时包含成功与失败

> 📖 **原文** (ch07 §7.4)：若G条响应全对（r i = 1 ∀ i）：所有advantage = 0，无学习信号！

> 📖 **原文** (ch07 §7.4)：若全错：同样的问题。Prompt难度必须与模型能力匹配。

> 📖 **原文** (ch07 §7.4)：Goldilocks原则：将prompt过滤至当前模型20–80%通过率。随着模型改进，每500步重新筛选。

🧭 **归纳**：组大小的选择逻辑（据原文表格还原）：

| G | 信号质量 | 算力 | 场景 |
|---|---|---|---|
| 低（2） | 不推荐——太嘈杂 | 低 | 极嘈杂（掷硬币） |
| 4 | 中等 | 中等 | 快速实验、简单任务（通过率 > 50%） |
| 8 | 良好（标准） | 高 | 默认，适合大多数任务 |
| 16 | 极佳 | 非常高 | 困难任务（通过率 < 20%），需多次尝试才能拿到正样本 |
| 32 | 近乎完美 | 极高 | 仅算力充裕且任务非常困难时 |

**核心约束**：组内必须同时包含成功与失败——全对或全错都会让归一化后的 advantage 全部为 0，没有学习信号。因此要按 **Goldilocks 原则**把 prompt 过滤到当前模型 20–80% 的通过率，并随模型进步每 500 步重新筛选。

## Q2-28 DAPO 对基础 GRPO 做了哪五项修复？

- 章节: ch07 §7.5.2　（原文：[ch07](../00-原书档案/fulltext/ch07.md)）
- 主题: DAPO 五组件

> 📖 **原文** (ch07 §7.5.2)：基础GRPO使用对称clipping：无论policy想增加还是减小某token的概率，约束都是相同的。但探索与利用具有不同的风险特征。增大一个好token的概率通常是安全的；而抑制一个恰好出现在坏completion中的token，若该token本身是中性的，则可能是灾难性的错误。DAPO [ 413 ]引入五项针对性修复，共同显著改进训练稳定性与最终性能。

> 📖 **原文** (ch07 §7.5.2)：组件2 —— Token级Loss聚合

> 📖 **原文** (ch07 §7.5.2)：组件5 ——动态采样（Dynamic Sampling）

> 📖 **原文** (ch07 §7.5.2)：DAPO会重新采样那些整组completion获得相同reward（全对或全错）的prompt，因为此类组在归一化后贡献零gradient。这能在整个训练过程中保持有效batch size稳定。

🧭 **归纳**：五项修复（据原文各组件小节还原）：

| # | 组件 | 解决的问题 |
|---|---|---|
| 1 | 非对称 clipping（Clip-Higher） | 对称 clip 同样限制「增大」与「减小」；好 token 可以多推一点，中性 token 不该被误杀。原文典型取值 ε = 0.2、ε_high = 0.28 |
| 2 | Token 级 loss 聚合 | 基础 GRPO 除以序列数 G，长 completion 会因 token 更多而主导梯度；改为除以总 token 数 |
| 3 | 过长过滤（Overlong Filtering） | 被截断的 completion 会惩罚那些其实生成正确的 token——整条 mask 掉 |
| 4 | 软过长惩罚 | 比硬 mask 更软：随长度接近上限平滑增长一个长度惩罚 |
| 5 | 动态采样 | 重采样全对或全错的组，维持有效 batch size |

原文给出的使用时机：completion 经常触及长度上限的长篇推理、观察到 reward 方差在训练中途坍塌、基础 GRPO 出现 loss 尖峰或熵坍塌——并推荐作为基础 GRPO 的即插即用改进。

## Q2-29 GSPO 与 TIS/MIS 分别在解决什么 off-policy 问题？

- 章节: ch07 §7.5.3 + ch07 §7.5.7　（原文：[ch07](../00-原书档案/fulltext/ch07.md)）
- 主题: 序列级重要性采样与 vLLM 概率修正

> 📖 **原文** (ch07 §7.5.3)：GRPO逐token地clip importance ratio。但一条500 token的序列，即使每个单独的ratio都在[1 − ϵ, 1 + ϵ ]内，逐token ratio的乘积可能大或小到天文数字。当在同一batch上进行多次gradient步（off-policy）时，这种不匹配迅速放大，clipping界限在序列级别上变得毫无意义。

> 📖 **原文** (ch07 §7.5.3)：• GRPO：独立clip | o i |个逐token ratio。一条序列可以所有ratio都在界内、却拥有10 50的乘积ratio。

> 📖 **原文** (ch07 §7.5.3)：• GSPO：对每条序列clip一次几何平均。保证序列级policy变化有界。

> 📖 **原文** (ch07 §7.5.3)：• GSPO在off-policy重要性采样上理论正确；GRPO只是近似。

> 📖 **原文** (ch07 §7.5.7)：当使用vLLM 进行快速生成时，vLLM 返回的log-probability 与训练前向传播中计算的不同[ 436 ]。这不是bug ——它源于不同的CUDA内核、不同的浮点精度以及不同的Attention实现（如FlashAttention vs PagedAttention）。

> 📖 **原文** (ch07 §7.5.7)：•当不匹配较小时（同模型、不同精度）首选TIS。

> 📖 **原文** (ch07 §7.5.7)：•当不匹配较大或不可预测时首选MIS。

🧭 **归纳**：两个不同的 off-policy 问题、两种修法：

**A. 序列级 clip 无界（GSPO）**——GRPO 逐 token clip，一条长序列的 ratio 连乘可以到天文数字，序列级别的约束实际失效。GSPO 把序列级 importance weight 定义为逐 token ratio 的几何平均（即完整序列概率比的 |o_i| 次方根），对每条序列只 clip 一次，从而保证序列级 policy 变化有界。原文判定：GSPO 在 off-policy 重要性采样上理论正确，GRPO 只是近似；纯 on-policy（steps_per_generation = 1）时两者差异可忽略。

**B. vLLM 与训练前向的 log-prob 不一致（TIS / MIS）**——这不是 bug，而是 CUDA 内核、浮点精度、Attention 实现不同造成的后果，但它悄悄破坏了 on-policy 假设：

- **TIS（Truncated IS）**：梯度乘一个截断的修正因子 min(π_train/π_vllm, C)。
- **MIS（Masked IS）**：修正比超过阈值 C 的序列，梯度直接置零——更保守。
- 选型：不匹配小 → TIS；不匹配大或不可预测 → MIS；序列级 IS 理论更正确，token 级是实用折中。

## Q2-30 「It Takes Two」洞见：G = 2 的 GRPO 为什么够用？

## Q2-34 Online DPO 怎么解决分布漂移？

- 主题: 在线采样的 DPO

> 📖 **原文** (ch08 §8.1.1)：标准DPO的主要局限：偏好数据由一个不同的模型生成（通常是较旧的checkpoint，甚至是不同的模型族）。随着训练推进，policy生成的文本与训练pair已完全不同→ loss在一个无关分布上进行优化。Online DPO方案[ 127 ]：每一步都从当前policy生成新鲜的偏好pair，用reward model判定，然后应用DPO loss。

> 📖 **原文** (ch08 §8.1.1)：3.构造pair：最高分= chosen，最低分= rejected

> 📖 **原文** (ch08 §8.1.1)：•与GRPO的关键差异：使用DPO loss（基于pair）而非PPO loss（逐样本advantage）

> 📖 **原文** (ch08 §8.1.1)：权衡：需要reward model（DPO不需要），但不需要value head（PPO需要）。复杂度居中。

## Q2-35 KTO 为什么能吃下未配对的点赞/点踩数据？

> 📖 **原文** (ch08 §8.2.1)：DPO需要成对偏好：对同一prompt，你既需要好的也需要坏的响应。实际上大多数反馈是未配对的：用户对单个响应给出点赞/点踩，没有匹配的pair。KTO的洞见[ 87 ]：使用前景理论（来自行为经济学）。人类对损失的感受比对收益更强烈。“点踩”应当产生比“点赞”更强的gradient。

> 📖 **原文** (ch08 §8.2.2)：关键优势：每个训练样本都是独立的！无需匹配pair。可直接使用点赞/点踩数据。

> 📖 **原文** (ch08 §8.2.2)：•二值化的人类评分（4–5星=好，1–2星=坏）

🧭 **归纳**：

- **数据格式差异**：KTO 只需 {prompt, completion, label: bool}，而 DPO 需要 {prompt, chosen, rejected}。
- **可直接吃下的数据**（据原文列表）：生产流量中的点赞/点踩、论坛赞/踩、二值化的人类评分（4–5 星=好，1–2 星=坏）、任何单条响应的质量信号。
- **损失厌恶**：好响应收益递减；坏响应惩罚加权更强。默认 λ_l = λ_w = 1.0，可以设 λ_l > λ_w。
- **何时选 KTO**（据原文 §8.2.4）：有二值反馈但没有匹配 pair；大规模生产点赞/点踩；一类占主导（如 90% 好 / 10% 坏，KTO 对不平衡更友好）；需要在噪声标签下快速迭代（对噪声比 DPO 更鲁棒）。

## Q2-36 IPO 修复了 DPO 的什么退化解？

- 章节: ch08 §8.3　（原文：[ch08](../00-原书档案/fulltext/ch08.md)）
- 主题: 目标 margin 与平方 loss

> 📖 **原文** (ch08 §8.3.1)：DPO有一个退化解：通过让chosen与rejected之间的margin无限大来达到零loss。实际上这意味着DPO会过拟合——把chosen概率推到1、rejected概率推到0，记住训练数据。IPO的修复[ 14 ]：与其使用会饱和的log-sigmoid，不如使用一个针对特定margin的平方loss。loss在有限差距处最小，而非无穷远。

> 📖 **原文** (ch08 §8.3.2)：DPO：σ (margin) → 1为最优。Margin →∞，没有自然停止点。IPO：Margin → 2 1 β为最优。平方loss同时惩罚过小与过大的margin。结果：IPO对噪声标签更鲁棒（错标的pair影响有界），且因为不死记硬背而泛化更好。

🧭 **归纳**：两者的停止点对比（据原文 §8.3.2）：

| | DPO | IPO |
|---|---|---|
| 最优 margin | σ(margin) → 1 | margin → 2/β（有界目标） |
| 停止点 | 没有自然停止点，margin 可趋于无穷 | 平方 loss 同时惩罚过小与过大的 margin |
| 对噪声标签 | 易受影响 | 更鲁棒（错标 pair 的影响有界） |
| 泛化 | 容易死记硬背训练数据 | 更好 |

**何时选 IPO**（据原文 §8.3.4）：噪声偏好数据（众包、AI 判定带错误）；观察到 DPO 过拟合（训练 loss → 0 但评估退化）；想要更保守更鲁棒的对齐；需要多个 epoch（DPO 在第一个 epoch 后就退化，IPO 更稳定）。

## Q2-37 ORPO 怎么把 SFT 和偏好对齐合并成一个 loss？

- 章节: ch08 §8.4　（原文：[ch08](../00-原书档案/fulltext/ch08.md)）
- 主题: 无 reference 的 SFT+对齐

> 📖 **原文** (ch08 §8.4.1)：迄今所有方法都需要参考模型——要么是独立副本（显存翻倍），要么通过LoRA隐式存在。ORPO [ 141 ]通过将监督微调（Supervised Fine-Tuning, SFT）与偏好对齐合并到单一loss中，彻底消除了参考模型。关键洞见：用生成chosen与生成rejected的odds ratio（几率比）作为偏好信号。SFT部分自然防止坍塌（无需KL正则）。

> 📖 **原文** (ch08 §8.4.2)：为什么不需要参考？SFT loss已将模型锚定在合理文本上，扮演了其他方法中KL-to-reference的角色。一个模型、一次前向、一个loss。显存减少50%！

> 📖 **原文** (ch08 §8.4.4)：•显存受限：负担不起参考模型副本（70B可节省70–140GB）

> 📖 **原文** (ch08 §8.4.4)：研究不如DPO/PPO充分—— 70B及以上规模的成熟配方较少

🧭 **归纳**：ORPO loss 两个分量（据原文公式 8.3 整理）：标准的 chosen 上的 NLL（SFT 项）+ odds ratio 项（偏好对齐项，权重 λ）。

- **SFT 项**：训练模型把 chosen 响应生成好。
- **Odds ratio 项**：额外推动模型偏好 chosen 而非 rejected，是天然的对比信号，不需要参考模型。
- **为什么能免 reference**：SFT loss 已把模型锚定在合理文本上，扮演了其他方法中 KL-to-reference 的角色。

**何时选 ORPO**（据原文 §8.4.4）：显存受限（负担不起参考模型副本）；从 base 模型起步（尚未 SFT，ORPO 同时做 SFT）；想要最简单的 pipeline（一模型、一 loss、一次训练）；一开始就有良好的偏好数据。

**局限**（原文自述）：研究不如 DPO/PPO 充分，70B 及以上成熟配方较少；SFT 部分意味着需要高质量的 chosen 响应（不仅是相对偏好）；调试更难（两个 loss 分量可能冲突）。

## Q2-38 Best-of-N 采样为什么值得当作 RL 的基线？

- 章节: ch08 §8.5　（原文：[ch08](../00-原书档案/fulltext/ch08.md)）
- 主题: 拒绝采样与 RFT

> 📖 **原文** (ch08 §8.5)：Best-of-N采样（Rejection Sampling）[ 262 ]在RL阶段完全不需要训练——只需生成多个候选并挑选最佳。

> 📖 **原文** (ch08 §8.5.2)：1.对每个prompt，从policy生成N条响应（通常N = 4–64）

> 📖 **原文** (ch08 §8.5.2)：N = 64时胜率比greedy提升10–20% ——有时匹配甚至超过PPO。

> 📖 **原文** (ch08 §8.5.2)：许多生产模型就是这样训练的：比PPO简单、几乎同样有效、完全稳定。

> 📖 **原文** (ch08 §8.5.4)：Best-of-N作为基线始终在相同算力预算下将你的RL方法与Best-of-N比较。若64 GPU-小时的PPO打不过64GPU-小时生成的Best-of-N，你的PPO有bug。

🧭 **归纳**：**算法四步**（据原文 §8.5.2）：生成 N 条候选（通常 N = 4–64）→ 用 reward model 打分 → 选最高分 →（可选）把选中响应作为下一轮 SFT 数据。

**两种用法**：

- **推理时**：不改模型权重，直接提升输出质量；N = 64 时胜率比 greedy 提升 10–20%，有时匹配甚至超过 PPO。
- **训练时（拒绝采样微调 / RFT）**：生成大量响应 → 选出最佳 → 在选中响应上做 SFT → 用更新后的模型重复（迭代精炼）。原文指出许多生产模型就是这样训练的。

**扩展律（据原文 Table 8.5.4）**：N=1 是基线（1× 成本）；N=4 约 +5–8% 胜率（最低有用值、良好的成本/质量比）；N=16 约 +10–15%（常匹配 PPO 质量）；N=64 约 +15–20%（开始边际递减）；N=256 约 +18–22%（仅用于关键应用）。

➕ **补充**：原文对 Best-of-N 的理论定位是它实现了隐式的 KL 约束 policy——分布形态正比于「原策略概率 × reward 的 1/N 次幂再归一化」，所以它不是纯粹的采样技巧，而是一种不需要梯度下降的对齐方式。

**扩展方向**：引入 margin m 保证胜出与落败 reward 之间存在最小间隔；以及 Plackett-Luce（用于排序）与多维奖励模型。

## Q2-44 多 reward 怎么组合？五种策略各有什么代价？

| 策略 | 做法 | 特点 |
|---|---|---|
| 加权求和 | r = Σ wₙ rₙ | 简单，但对尺度敏感 |
| 先归一化再求和（GDPO） | 组内各自归一化为零均值单位方差后再加权求和 | 尺度无关 |

## Q2-45 为什么要用 listwise 奖励模型？Plackett-Luce 是什么？

- 章节: ch09 §9.7　（原文：[ch09](../00-原书档案/fulltext/ch09.md)）
- 主题: 从成对到排序

> 📖 **原文** (ch09 §9.7)：虽然Bradley-Terry模型处理的是成对偏好（y w ≻ y l），但许多实际场景需要同时对多个回答进行排序。列表式（listwise）奖励模型从完整排序中学习，提供更丰富的训练信号，并实现更好的校准。

> 📖 **原文** (ch09 §9.7)：•更好的校准：成对BT模型只学习Reward的差值；listwise模型学习的是绝对Reward尺度。

> 📖 **原文** (ch09 §9.7)：•天然契合GRPO：GRPO对每个prompt生成N个回答并排序—— listwise Reward与该工作流直接对齐。

> 📖 **原文** (ch09 §9.7)：•标注效率：对5个回答排序比独立标注所有10个可能的成对组合更快。

> 📖 **原文** (ch09 §9.7)：Plackett-Luce(PL)模型[ 291 ]是将Bradley-Terry推广至完整排序的标准扩展。

> 📖 **原文** (ch09 §9.7)：•列表长度：训练时K = 4–8较为常见。更长的列表（K > 16）只会增加噪声，收益有限。

🧭 **归纳**：

**四条动机**（据原文 §9.7 列表）：① 更丰富的信号（K 个回答的排序包含相对 margin，如第 1 比第 3 好多少）；② 更好的校准（成对 BT 只学差值，listwise 学绝对尺度）；③ 天然契合 GRPO 的「N 个回答打分排序」工作流；④ 标注效率更高（排 5 个比标注 10 个成对组合更快）。

**Plackett-Luce**：把 BT 推广到完整排序。直觉是顺序地从剩余项中选出最佳——每一步选中当前最优的概率是对剩余项做 softmax。当 K = 2 时它退化为 BT，因此 PL 是 BT 的严格推广。

**实用考量**（据原文）：完整排序昂贵，部分排序（8 个中取 top-3）能显著降本；并列可用 PL 的并列扩展处理；注意位置偏差（标注者偏好排在前面的项）；列表长度 K = 4–8 最常见，K > 16 只增加噪声；用标注者间一致性（κ > 0.6）做质量过滤。

| 参数状态 | 先验知识被物理覆盖 | 潜在分布被约束/截断 |
| 信息 | 被摧毁：权重不再编码该能力 | 被抑制：知识仍存在但更难触发 |
| 主导阶段 | SFT、领域继续预训练 | 偏好优化（PPO、DPO、KTO、RLHF） |
| 主要症状 | 基线能力完全崩溃 | 过度拒答、风格僵硬、原始基准分数下降 |
| 可逆性 | 不重新从 checkpoint 训练则不可逆 | 部分可逆：调整 β、system prompt 或微调 |
| 随模型规模 | 各尺度相近 | 小模型支付更大的对齐税 |

➕ **补充**：混淆这两者会导致用错缓解手段——遗忘要靠数据回放 / LoRA，对齐税要靠调 β / 控制 RL 预算；给对齐税加数据回放是浪费，给遗忘调 β 则完全无效。

## Q2-51 怎么判断遇到的是遗忘还是对齐税？各自怎么缓解？

- 章节: ch10 §10.5.4　（原文：[ch10](../00-原书档案/fulltext/ch10.md)）
- 主题: 诊断方法与缓解手段

> 📖 **原文** (ch10 §10.5.4)：•在失败任务上运行base模型：若base模型成功而微调后模型完全失败→灾难性遗忘。

> 📖 **原文** (ch10 §10.5.4)：•困惑度检查：在预训练验证集上计算困惑度。飙升=遗忘。稳定=对齐税。

> 📖 **原文** (ch10 §10.5.4)：1.数据回放（Data replay）：将5–10%的预训练数据混入SFT数据集。确保Gradient更新不会完全忽视预训练分布。

> 📖 **原文** (ch10 §10.5.4)：5.渐进式训练：逐步混合分布，随时间增加SFT数据比例，而非突然切换。

> 📖 **原文** (ch10 §10.5.4)：5.有针对性的RL预算：不要过度训练RL。监控能力基准，当税负超出可接受阈值（通常是2–5% MMLU回退）时停止。

🧭 **归纳**：

**四种诊断手段**（据原文）：① 在失败任务上跑 base 模型——base 成功而微调后完全失败 → 遗忘；② Prompt 工程测试——精心设计的 prompt 能恢复能力 → 对齐税；③ 预训练验证集上的困惑度——飙升 = 遗忘，稳定 = 对齐税；④ Few-shot 恢复——少量示例能恢复 = 对齐税，大量示例也不行 = 遗忘。

**遗忘的缓解手段**（据原文五条）：数据回放（混入 5–10% 预训练数据）；弹性权重整合 EWC（惩罚 Fisher 信息高的参数变化）；LoRA / 参数高效微调（只训低秩 adapter，基础权重冻结）；保守学习率（1–5 × 10⁻⁶ + 1–3 个 epoch）；渐进式训练。

> 📖 **原文** (ch10 §10.5.4)：3.LoRA /参数高效微调：只训练低秩adapter（参数量< 1%），基础权重完全冻结。这避免了预训练知识的永久性摧毁——你随时可以移除adapter来恢复原模型。然而，当adapter处于激活状态时，组合系统( W 0 + BA )仍可能表现出遗忘：adapter可能将模型的有效行为推离旧技能。LoRA保护的是checkpoint，而非激活时的推理行为。

**对齐税的缓解手段**（据原文五条）：仔细调节 β（多数场景最优 β ∈ [0.05, 0.3]）；高质量、多样化的 SFT 数据；条件对齐；Constitutional AI / RLAIF；有针对性的 RL 预算（能力基准回退 2–5% 即停）。

## Q2-52 RL 之前为什么要先测 SFT 模型的 pass@k？

- 章节: ch10 §10.6　（原文：[ch10](../00-原书档案/fulltext/ch10.md)）
- 主题: RL 的可行性门槛

> 📖 **原文** (ch10 §10.6)：为使RL起作用，SFT模型必须偶尔产生正确响应（从而Reward信号非零）。如果SFT模型对某prompt从不产生正确响应，RL无法学会产生正确响应——没有可放大的正向信号。这就是为什么SFT质量是RL性能的上限。

> 📖 **原文** (ch10 §10.6)：具体而言：若SFT模型能正确解答10%的数学题，RL有可能将其推至80%。若SFT模型解题率为0%,RL将毫无进展（所有Reward为零，所有优势为零，无Gradient）。

> 📖 **原文** (ch10 §10.6)："""估计SFT模型的pass@k 。若pass@1 < 5%,RL大概率会失败。若pass@k < 20%,RL会很吃力。"""

> 📖 **原文** (ch10 §10.6)：2.SFT数据覆盖度：确保SFT数据覆盖你想通过RL改进的任务。如果某任务不在SFT数据中，RL将难以推进。

> 📖 **原文** (ch10 §10.6)：3.SFT训练时长：不要过度训练SFT模型。过度训练降低多样性，让RL探索更困难。

🧭 **归纳**：门槛与四条实践启示（据原文 §10.6）：

- **门槛**：pass@1 < 5% → RL 大概率失败；pass@k < 20% → RL 很吃力。原文给的量级参照是「SFT 解答率 10% → RL 可能推到 80%；解答率 0% → 毫无进展」。
- **为什么**：RL 只能放大已有的正向信号；所有 reward 为零时，所有 advantage 为零，没有梯度。
- **实践**：① 用高质量、多样化数据；② 覆盖度要对齐 RL 想改进的任务；③ 不要过度训练 SFT（降低多样性会让 RL 探索更难）；④ 即使 base 模型已指令微调过，RL 前仍可做简短的 SFT warm-up。

原文的 SFT 最佳实践八条小结另见章末：序列打包、completion-only masking、正确 chat 模板、温度缩放混合、LoRA 防遗忘、RL 前评估 pass@k、不过度训练（1–3 个 epoch）、监控多样性指标检测 mode collapse。

## Q2-54 张量并行为什么必须限制在节点内？

- 章节: ch11 §11.2.2　（原文：[ch11](../00-原书档案/fulltext/ch11.md)）
- 主题: TP 度与跨节点扩展

> 📖 **原文** (ch11 §11.2.2)：张量并行（Megatron-LM风格[ 327 ]）把单个权重矩阵切到多块GPU上。每块GPU计算部分结果，再通过AllReduce合并。

> 📖 **原文** (ch11 §11.2.2)：每个Transformer层需要2次AllReduce操作（上文标注为f和g）。对于80层的70B模型，每次前向就是160次AllReduce（算上反向共320次）。

> 📖 **原文** (ch11 §11.2.2)：规则：TP度≤节点内GPU数（通常TP ≤ 8）。跨节点扩展请用DP/FSDP。

> 📖 **原文** (ch11 §11.2.2)：重要：attention head数必须能被TP度整除。例如LLaMA-70B（64个head），合法的TP取值为1、2、4、8、16、32、64。

🧭 **归纳**：**通信代价的量化推导**（据原文）：每个 Transformer 层 2 次 AllReduce；80 层 70B 模型单次前向即 160 次（连反向 320 次）。在 NVLink（600 GB/s）下每次 AllReduce < 0.5 ms；在 InfiniBand（50 GB/s）下同一操作约 4 ms，总开销 160 × 4 = 640 ms——比计算本身还长。由此得出硬规则：TP 度 ≤ 节点内 GPU 数。

**TP 度的选取（据原文）**：

| TP 度 | 适用 | 开销 |
|---|---|---|
| 1 | 模型可放进单 GPU（BF16 通常 ≤ 13B） | —— |
| 2 | 13–34B 推理 | < 5% |
| 4 | 34–70B 推理标准配置 | 8–12% |
| 8 | 占满整节点，70B+ 训练必备 | 12–18% |
| > 8 | 跨节点 TP，极少使用（仅 200B+ 且 PP 装不下） | 30–50% |

**硬约束**：attention head 数必须能被 TP 度整除（LLaMA-70B 64 heads → 合法 TP 取 1/2/4/8/16/32/64）。

## Q2-55 序列并行解决了什么 TP 解决不了的显存问题？

- 章节: ch11 §11.2.3　（原文：[ch11](../00-原书档案/fulltext/ch11.md)）
- 主题: LayerNorm/Dropout 激活显存

> 📖 **原文** (ch11 §11.2.3)：序列并行（Sequence Parallelism, SP）[ 191 ]解决的是张量并行单独无法消除的一个显存瓶颈：LayerNorm和Dropout层中的激活值显存。

> 📖 **原文** (ch11 §11.2.3)：问题。TP把权重显存切到了多块GPU上。但LayerNorm和Dropout作用在完整的hidden维上，并在每块GPU上都重复存在。

> 📖 **原文** (ch11 §11.2.3)：总通信量完全相同！SP是零额外通信开销的纯显存优化，使用TP时应当始终开启。

🧭 **归纳**：

**问题**：TP 切的是权重，但 LayerNorm / Dropout 作用在完整 hidden 维上，每块 GPU 都在重复算，激活显存（反向需要）与 b×s×d 成正比，TP 降不下来。

**解法**：对这些不需要跨 GPU 通信的操作按序列维切分，每块 GPU 只处理 s/T 的切片，仅在真正需要处（attention、线性层）再 gather 出完整序列。

**为什么「免费」**：标准 TP 每个子层后的 AllReduce 等价于 ReduceScatter + AllGather；SP 只是把这两个原语重排为 ReduceScatter → 在 1/T 的部分张量上算 LayerNorm → 进入下个 TP 层前 AllGather。总通信量完全相同，因此是零额外通信开销的纯显存优化。

原文给的量化：70B、TP=8、batch=4、seq=2048 时激活值节省约 59 GB/GPU。

## Q2-56 流水线并行里的「气泡」是什么？1F1B 解决了什么？

- 章节: ch11 §11.2.4　（原文：[ch11](../00-原书档案/fulltext/ch11.md)）
- 主题: PP 气泡与调度策略

> 📖 **原文** (ch11 §11.2.4)：流水线并行把模型按层纵向切分，把连续的层组指派给不同的设备（stage）。激活值在stage间向前流动，梯度向后流动。

> 📖 **原文** (ch11 §11.2.4)：1F1B（one-forward-one-backward）调度[ 263 ]被大多数生产系统采用（Megatron-LM [ 264 ]、DeepSpeed [ 304 ]）：预热：前向先填满流水线（P-1个micro-batch）。

> 📖 **原文** (ch11 §11.2.4)：显存优势：GPipe必须同时保存全部M个micro-batch的激活值。1F1B在稳态下只保存P组激活值——当M = 32而P = 4时至关重要。

> 📖 **原文** (ch11 §11.2.4)：把更多Transformer层分配给中间stage，第一/最后stage少放一些，以平衡计算。

🧭 **归纳**：

**气泡**：某个 stage 等待前一 stage 输入或后一 stage 梯度时的空闲时间。气泡占比随 micro-batch 数 M 增大而下降（原文公式 11.3），要让气泡开销 < 10% 需 M ≥ 10·(P−1)，PP=4 时至少需要 30 个 micro-batch。

**调度策略对比（据原文 Table 11.1 还原）**：

| 调度 | 气泡 | 显存 | 特性 |
|---|---|---|---|
| GPipe | (P−1)/M | M × 激活 | 简单；先全部前向再全部反向 |
| 1F1B | (P−1)/M | (M+P−1) | 交错；稳态显存有界——生产标准 |
| Interleaved 1F1B | (P−1)/(M·V+P−1) | 值 | 虚拟 stage，进一步减小气泡 |
| Zero-Bubble（ZB-H1） | ≈ 0 | P × 激活 | 把反向拆成 B 和 W 两个阶段 |

**负载均衡**：Embedding 层很便宜、Transformer block 计算量均匀、末尾 LM head 中等；应把更多 Transformer 层分配给中间 stage。

**PP 的通信**：只需相邻 stage 之间的点对点激活值通信，远小于 TP 的 AllReduce。

## Q2-57 FSDP / ZeRO-3 换来了什么？代价是什么？

- 章节: ch11 §11.2.5　（原文：[ch11](../00-原书档案/fulltext/ch11.md)）
- 主题: 完全分片与通信量

> 📖 **原文** (ch11 §11.2.5)：FSDP [ 431 ]（PyTorch）和ZeRO-3 [ 304 ]（DeepSpeed）解决了DDP固有的显存重复问题：不再让每块GPU都保存完整的参数、梯度和优化器状态，而是每块GPU只拥有1 /N的切片，需要时即时重建完整张量。

> 📖 **原文** (ch11 §11.2.5)：• FSDP：2次AllGather（前向+反向）+ 1次ReduceScatter = 3 M字节。

> 📖 **原文** (ch11 §11.2.5)：这就是显存与通信的取舍。FSDP值得使用的场景是：(a)模型在DDP下无法装进GPU显存；或(b)通信与计算重叠得很好（现代框架可达到70–90%重叠）。

🧭 **归纳**：每层三步执行流程（据原文）：

1. **前向**：AllGather 参数 → 计算 → 丢弃非自有分片。
2. **反向**：再次 AllGather 参数 → 算梯度 → ReduceScatter 梯度（每 GPU 拿到自己的分片）→ 丢弃非自有分片。
3. **优化器更新**：每 GPU 只用自己持有的梯度分片和优化器状态更新自己拥有的分片。

**通信量对比（据原文）**：DDP 每步 1 次梯度 AllReduce = 环上合计 2M 字节；FSDP 每步 2 次 AllGather + 1 次 ReduceScatter = 3M 字节——**FSDP 的通信量是 DDP 的 3 倍**。

**ZeRO 阶段的渐进（据原文 Table 11.2 / 11.6，70B 8 GPU）**：

| 策略 | 分片对象 | 每 GPU 显存 |
|---|---|---|
| 无（纯数据并行） | 无 | 560 GB（不可行） |
| ZeRO-1 | 仅优化器状态 | 175 GB |
| ZeRO-2 | 优化器状态 + 梯度 | 105 GB |
| ZeRO-3 / FSDP | 优化器 + 梯度 + 参数 | 70 GB（A100-80GB 装得下） |

**何时值得用**：模型在 DDP 下装不进显存，或通信与计算重叠得很好（现代框架可达 70–90% 重叠）。

## Q2-59 解耦 DiLoCo 怎么让训练跨出单个数据中心？

- 章节: ch11 §11.2.7　（原文：[ch11](../00-原书档案/fulltext/ch11.md)）
- 主题: 低带宽跨区域训练

> 📖 **原文** (ch11 §11.2.7)：常规分布式训练假设高带宽互联——单个数据中心内的100+ Gbps InfiniBand。这一要求使得用标准互联网链路跨地理分布式数据中心训练成为不可能。解耦DiLoCo（Decoupled DiLoCo）[ 114 ]（Google DeepMind，2026年4月）打破了这一假设，让大规模训练可以在普通带宽下跨区域进行。

> 📖 **原文** (ch11 §11.2.7)：只有外部更新（每H步一个模型大小的张量）会穿越网络——而不是逐步骤的梯度。

> 📖 **原文** (ch11 §11.2.7)：•带宽降低：比同步分布式训练少用236 ×的带宽。

> 📖 **原文** (ch11 §11.2.7)：•速度：比完全异步SGD（受陈旧梯度困扰）快20 ×的墙钟时间。

> 📖 **原文** (ch11 §11.2.7)：关键洞见是：现代优化器对低频、带噪声的外部更新具有鲁棒性——内部训练步骤提供了足够的局部信号，外部同步只需要纠正分布漂移即可。

🧭 **归纳**：**DiLoCo 的核心思想**（据原文三步）：每个 Worker 在本地数据分片上独立训练 H 个内部步骤 → H 步后各 Worker 计算一个「外部更新」（各自权重相对共享起始点的差值，按 Worker 数求平均）→ 外部更新经一个全局优化器（如 Nesterov 动量）应用，所有 Worker 重置到新的共享权重。

**解耦 DiLoCo** 进一步解耦了外部同步：Worker 无需同时同步，更新跨区域异步到达，由协调者在更新到达时应用——从而容忍广域网的可变延迟。

**实证**（12B 模型，4 个美国区域，标准互联网链路 2–5 Gbps）：带宽比同步分布式训练少用 236 倍；比完全异步 SGD 快 20 倍墙钟时间；标准语言建模基准上与单数据中心训练持平；Worker 故障只延迟外部更新而不拖垮整个训练。

**为什么可行**：现代优化器对低频、带噪声的外部更新具有鲁棒性——内部训练步骤提供足够的局部信号，外部同步只需纠正分布漂移。

原文还列出四个战略意义：主权 AI（敏感数据不必经过中央设施）、多云训练（竞价实例 + 绕开故障）、数据中心韧性、异构硬件。

## Q2-60 为什么生成本身是显存带宽瓶颈？怎么优化？

- 章节: ch11 §11.3　（原文：[ch11](../00-原书档案/fulltext/ch11.md)）
- 主题: Roofline 分析与加速栈

> 📖 **原文** (ch11 §11.3)：Roofline拐点：312T / 2T = 156 FLOP/byte。低于156 FLOP/byte的操作受显存带宽约束。

> 📖 **原文** (ch11 §11.3)：利用率：1 / 156 = 0 . 6%的峰值FLOPS。GPU有99.4%的时间在等显存读。

> 📖 **原文** (ch11 §11.3)：3.推测解码（Speculative decoding）[ 205 ]（2–3 ×）：小draft模型一次猜5个token，大模型一次前向就能验证。平均接受3–4个。

> 📖 **原文** (ch11 §11.3)：4.生成用INT8/FP8权重（2 ×）：带宽需求减半。因为我们在做采样（不是为训练算精确logits），质量损失极小。

🧭 **归纳**：**定量论证**（据原文，A100：312 TFLOPS BF16 + 2 TB/s HBM）：

- Roofline 拐点 156 FLOP/byte。自回归生成 batch=1 时，每生成一个 token 要读完 70B 的全部权重（140GB）、只做 2×70B = 140 GFLOPs，算术强度 = 1 FLOP/byte——比拐点低 156 倍，**峰值 FLOPS 利用率只有 0.6%**。
- 单流 token 速率 = 2TB/s ÷ 140GB ≈ 14.3 tok/s；生成 512 token 约 35.8 秒/条。
- Batch 化能改善：batch=64、TP=4 时算术强度升到 64 FLOP/byte，仍在拐点之下。

**加速栈（各项可累乘，据原文）**：

| 手段 | 加速比 | 原理 |
|---|---|---|
| vLLM + PagedAttention | 2–4× | 消除 KV cache 碎片，使更大 batch 成为可能 |
| 连续 batching | 1.5–2× | 不必等最长序列结束，一有序列结束就插入新的 |
| 推测解码 | 2–3× | 小 draft 模型一次猜 5 个 token，大模型一次前向验证，平均接受 3–4 个 |
| 生成用 INT8/FP8 | 2× | 带宽需求减半；因为是采样而非为训练算精确 logits，质量损失极小 |
| CUDA graphs | 1.1–1.3× | 消除固定形状操作的 kernel 启动开销 |
| Prefix caching | 1.5× | 共享前缀 prompt 下不重算 system prompt 的 KV cache |

## Q2-61 为什么要把生成与训练拆成独立集群？权重同步能滞后吗？

- 章节: ch11 §11.4 + ch11 §11.5　（原文：[ch11](../00-原书档案/fulltext/ch11.md)）
- 主题: 解耦架构与同步滞后

> 📖 **原文** (ch11 §11.4)：生成受显存带宽约束（需要高速HBM，浪费算力）。

> 📖 **原文** (ch11 §11.4)：训练受算力约束（需要tensor core，反向时浪费带宽）。

> 📖 **原文** (ch11 §11.4)：• gen(step N + 1)与train(step N )可重叠→ 30–40%加速

> 📖 **原文** (ch11 §11.5)：PPO的裁剪目标本来就是为离策略数据设计的！裁剪区间[1 − ϵ, 1 + ϵ ]限制了陈旧数据的影响。当滞后在10–50步时：

> 📖 **原文** (ch11 §11.5)：•经验上：50步滞后的质量损失< 2%

🧭 **归纳**：**解耦的硬件理由**——生成与训练受的是两种不同的资源约束，混在同一批硬件上必然有一方被浪费：要么生成时浪费算力，要么训练时浪费带宽。拆开后每簇都能用最优硬件/配置（生成用 INT8 带宽优先，训练用 BF16 精度优先）。

**解耦带来的工程好处**（据原文）：生成与训练可独立扩展；生成集群无状态→容错极简；gen(step N+1) 与 train(step N) 可重叠 → 30–40% 加速；可用不同精度。

**权重同步策略（据原文表格还原）**：

| 策略 | 滞后 | 带宽 | 质量影响 |
|---|---|---|---|
| 同步（每步） | 0 步 | 140 GB/步 | 完美但太慢 |
| 周期性（每 50 步） | 平均 25 步摊销 | 2.8 GB/步 | 质量损失 < 2% |
| Delta 压缩（INT8） | 平均 25 步 | 0.4 GB/步 | 质量损失 < 3% |
| 异步流式 | 5–10 步 | 14 GB/步（后台） | 质量损失 < 1% |

**为什么能容忍滞后**：clipping 区间本身就限制陈旧数据的影响。合理学习率下每步 policy 变化约 0.1–1%，50 步累计约 5% 漂移，而 PPO clipping 能处理高达 20% 的漂移——原文经验值是 50 步滞后质量损失 < 2%。

带宽账：70B BF16 = 140GB，InfiniBand 400Gb/s = 50GB/s → 完整同步 2.8s；配合 delta 压缩 < 0.5s；异步同步在后台跑等于免费。

## Q2-62 RL 训练的优化器配置为什么不能照搬 SFT？

- 章节: ch11 §11.15　（原文：[ch11](../00-原书档案/fulltext/ch11.md)）
- 主题: LR、调度、beta2、精度与裁剪

> 📖 **原文** (ch11 §11.15.1)：•不用weight decay：正则化由KL惩罚提供，而不是weight decay。再叠加WD可能与KL约束相互对抗。

> 📖 **原文** (ch11 §11.15.1)：•更短的warmup：RL 从已收敛的SFT checkpoint 起步——优化器状态只需极短的warmup。

> 📖 **原文** (ch11 §11.15.3)：Adam默认的β 2 = 0 . 999给二阶矩留下了非常长的记忆（有效窗口∼ 1000步）。在RL训练中，loss地形随policy演化迅速变化—— 1000步前的梯度方差已无关紧要。使用β 2 = 0 . 95把窗口缩短到∼ 20步，让自适应学习率能够迅速响应变化中的梯度统计。

> 📖 **原文** (ch11 §11.15.4)：RL训练务必使用FP32 master权重。纯BF16训练（不留FP32副本）几乎必然会让PPO/GRPO在100–500步后出现reward崩塌。

> 📖 **原文** (ch11 §11.15.5)：哪怕只有一步∥∇∥ > 50的未裁剪更新，都可能让数百步训练前功尽弃。

🧭 **归纳**：RL 与 SFT 的五条关键差异（据原文 §11.15.1）：

| 差异 | 后果 |
|---|---|
| 数据分布非平稳 | 每轮迭代生成新 rollout，数据分布随 policy 一起漂移 |
| 高梯度方差 | reward 信号稀疏且嘈杂，远高于精选数据上的交叉熵 |
| 需要更小的更新 | policy 必须贴近 reference（KL 约束），学习率比 SFT 小 10–100 倍 |
| 不用 weight decay | 正则化由 KL 惩罚提供，叠加 WD 会与 KL 约束相互对抗 |
| 更短的 warmup | 从已收敛的 SFT checkpoint 起步，只需极短 warmup |

**各 RL 方法的推荐超参（据原文 Table 11.2，均用 β₁=0.9、β₂=0.95、ε=1e-8、max_grad_norm=1.0、BF16）**：

| 方法 | 优化器 | LR | WD | Warmup | 调度 |
|---|---|---|---|---|---|
| DPO | AdamW | 5e-7 | 0.0 | 50 步 | Constant 或 Linear |
| PPO（policy） | AdamW | 1e-6 | 0.0 | 20 步 | Constant |
| PPO（critic） | AdamW | 1e-6 | 0.0 | 20 步 | Constant |
| GRPO | AdamW | 1e-6 | 0.0 | 20 步 | Constant |

**为什么用恒定调度**：Cosine 与线性衰减都假设训练 horizon 固定、loss 单调下降，而 RL 两者都不具备——reward 可能停滞、尖峰或不可预测地震荡。

**精度与裁剪**：β₂=0.95 把二阶矩窗口从约 1000 步缩到约 20 步；但 batch 极小时（如在线 RL 的 batch=1）β₂=0.95 会让二阶矩估计噪声过大，需退回 0.99 或加大梯度累积。RL 必须用 FP32 master 权重——因为学习率在 10⁻⁶–10⁻⁷ 量级，BF16 的 7 位尾数无法表示相对 10⁰ 量级权重的 10⁻⁶ 量级更新。梯度裁剪 `max_grad_norm=1.0` 是标准设置，RL 下更关键（SFT 的梯度 norm 稳定在 0.1–1.0，RL 的梯度是尖刺型的）。

## Q2-66 轨迹缓冲区有哪三种利用范式？

- 章节: ch12 §12.3　（原文：[ch12](../00-原书档案/fulltext/ch12.md)）
- 主题: 自我纠正 / 离策略探索 / 非参数化检索

> 📖 **原文** (ch12 §12.3)：LLM Agent通过三种主要的优化方法论来利用专门的轨迹缓冲区：

> 📖 **原文** (ch12 §12.3.2)：•成功过滤：只保留达成目标的轨迹用于训练。

> 📖 **原文** (ch12 §12.3.2)：•效率排序：在成功轨迹中，优先选择最短/最高效的工具使用路径。

> 📖 **原文** (ch12 §12.3.2)：•多样性采样：维持多样化的解决策略集合，以防止模式坍塌。

> 📖 **原文** (ch12 §12.3.3)：•需要零训练——纯粹的检索增强生成（Retrieval-Augmented Generation, RAG）

> 📖 **原文** (ch12 §12.3.3)：•与参数化学习互补（罕见情况使用检索，常见模式使用权重）

🧭 **归纳**：

| 范式 | 代表 | 做什么 |
|---|---|---|
| A. 自我纠正与思维细化 | STaR、Reflexion | 失败轨迹被采样并让 LLM 对自己的表现生成显式文本批评；修正后拿到正 reward 的轨迹移入最优经验池，用于 SFT 或 GRPO 更新权重 |
| B. 离策略探索 | ReAct 等 | Agent 记录数千条探索性执行路径，缓冲区当过滤器：只留成功的、优先最短/最高效的路径、维持多样性防止模式坍塌；优化算法只在这类轨迹上算 loss |
| C. 非参数化上下文学习 | 基于经验的 RAG | 缓冲区不碰网络权重，而是当向量数据库：检索与新目标最相似的过往经验，Top-k 成功历史运行作为 few-shot 示例直接注入 prompt |

➕ **补充**：第三种范式常被低估——它零训练成本、随缓冲区规模线性扩展覆盖，且与参数化学习互补（罕见情况用检索，常见模式用权重），是 12.8.4 混合路线的低风险入口。

## Q2-67 STaR 和 Reflexion 这两条「无梯度 / 弱梯度」路线分别怎么工作？

> 📖 **原文** (ch12 §12.5.2)：Reflexion [ 326 ]引入了一种激进的范式：无权重更新的RL。Agent不通过基于梯度的学习，而是通过存储在情节记忆中的自然语言自我批评来改进。

## Q2-68 AgentQ 怎么把 DPO 搬到 Agent 轨迹上？

- **硬约束**（动作立即被拒、reward = −1.0）：未确认即对外发邮件/消息；永久删除文件/邮件（仅允许软删除）；修改共享资源权限；越权访问他人邮箱或文件；单 batch 内对超过 100 个条目执行动作（防批量事故）。

## Q2-71 Agent 训练该用 GRPO 还是 PPO？稀疏 reward 怎么解？

- 章节: ch12 §12.8　（原文：[ch12](../00-原书档案/fulltext/ch12.md)）
- 主题: Agent RL 的算法选型与信用分配

> 📖 **原文** (ch12 §12.8.1)：•无critic：节省50% GPU 内存——当Agent 轨迹已经占用了庞大的上下文窗口（32K–128KToken）时至关重要。

> 📖 **原文** (ch12 §12.8.1)：•自然契合：Agent任务通常有二元可验证reward（测试通过/失败、目标达成/未达成）——非常适合组相对归一化。

> 📖 **原文** (ch12 §12.8.2)：•通过GAE进行步骤级优势估计，处理可变长度的工具输出

> 📖 **原文** (ch12 §12.8.2)：•权衡：需要2 ×内存（critic）但提供更密集的学习信号

> 📖 **原文** (ch12 §12.8.3)：Agent RL的核心挑战是稀疏reward问题。如果Agent执行20个工具动作并最终未通过一个单元测试，终端reward为0会平等地惩罚所有20个动作。

> 📖 **原文** (ch12 §12.8.3)：中间reward为每一步都提供梯度信号，而不仅是最后一步。这相比仅有稀疏reward的情况，将学习速度显著加速3–5 ×。

🧭 **归纳**：**为什么 GRPO 主导 Agent 训练**（据原文 §12.8.1）：无 critic 省 50% GPU 内存——Agent 轨迹本身就占 32K–128K token 上下文，显存极其紧张；Agent 任务天然多为二元可验证 reward，非常适合组相对归一化；每个任务采样 N 条多样化轨迹，天然探索不同工具使用策略。

**PPO 仍有价值的场景**（据原文 §12.8.2）：环境高度随机、步骤级 value 估计有帮助时——通过 GAE 做步骤级优势估计以处理可变长度的工具输出；value 头学习预测「从这里开始这条轨迹有多大可能成功」；外部工具返回灾难性错误导致 reward 方差激增时更稳定。代价是需要 2 倍内存。

**细粒度信用分配的两条路**（据原文 §12.8.3）：

1. **RLVR 中间奖励**：在确定性检查点给 reward（bash 编译成功 +0.1、浏览器定位到正确元素 +0.2、SQL 返回非空 +0.1、最终测试套件通过 +1.0），使学习速度提升 3–5 倍。
2. **多轮轨迹切片**：重放成功前缀 → 识别第一个偏离点 → 只对该步骤给负 reward → 对正确前缀给中性/正 reward，从而做外科手术式的 policy 更新。

**范式对比（据原文 Table 12.9）**：GRPO reward 密度为序列/最终指标、内存成本低；PPO 为逐步（GAE）、内存成本高但信用分配细；迭代式 STaR 内存成本极小、易扩展且避免 RL 不稳定性；RWML 用密集的预测式 reward 缓解 reward hacking；LATS 通过树反向传播、用推理算力换质量。

> 📖 **原文** (ch08 §8.6)：3.有成对偏好吗？→ DPO（若噪声大则用IPO）

> 📖 **原文** (ch08 §8.6)：4.仅有未配对的二值反馈？→ KTO

> 📖 **原文** (ch08 §8.6)：5.显存受限、从base模型起步？→ ORPO

> 📖 **原文** (ch08 §8.6)：6. DPO停滞、想要on-policy？→ Online DPO

> 📖 **原文** (ch08 §8.6)：7.需要快速建立强基线？→ Best-of-N / RFT

🧭 **归纳**：把第 4 章的定位与第 8 章的决策树合起来看：

| 起点条件 | 选谁 | 理由（原文口径） |
|---|---|---|
| 有可验证 reward（数学/代码） | GRPO | DeepSeek 的无 critic 算法，用组级 reward 归一化，DeepSeek-R1 背后的方法、推理模型训练的主导选择 |

| 有成对偏好 | DPO（噪声大用 IPO） | 绕开 RL，直接把偏好变成对比式有监督 loss |

## Q2-73 跨章对照：省显存的「去 critic」与「去 reference」两条路线

- 章节: ch05 §5.1 + ch06 §6.1 + ch07 + ch08 §8.4　（原文：[ch05](../00-原书档案/fulltext/ch05.md) / [ch06](../00-原书档案/fulltext/ch06.md) / [ch07](../00-原书档案/fulltext/ch07.md) / [ch08](../00-原书档案/fulltext/ch08.md)）
- 主题: 两条减负路线

> 📖 **原文** (ch06 §6.1)：PPO需要在显存中维持4个模型（policy、reference、reward模型、value head）、复杂的RL基础设施，并且以不稳定著称。

> 📖 **原文** (ch07)：组相对策略优化（Group Relative Policy Optimization, GRPO）[ 323 ] 是一种专为语言模型设计的强化学习算法，它消除了对独立value network（critic）的需求。

> 📖 **原文** (ch07)：这从显存中去掉了一整个模型，将工程复杂度减半，而且——令人意外的是——往往优于PPO，因为经验基线比训练不充分的value function更准确。

> 📖 **原文** (ch08 §8.4.1)：ORPO [ 141 ]通过将监督微调（Supervised Fine-Tuning, SFT）与偏好对齐合并到单一loss中，彻底消除了参考模型。

> 📖 **原文** (ch05 §5.1)：2. PPO（2017）[ 319 ]：用一个简单的一阶clipped 目标实现类似的稳定性。实现复杂度低了10 ×，效果几乎一样，且能轻松扩展到分布式训练。

🧭 **归纳**：PPO 的四份显存里，有两份是「可以被拆掉」的——两条路线各砍掉一份：

| 路线 | 砍掉什么 | 代表方法 | 代价 |
|---|---|---|---|
| 去 critic | value network | GRPO（组内 reward 归一化替代 V(s)） | 需要 reward 可比；组内必须同时有成功与失败（Q2-26）；无法跨 prompt 迁移基线 |
| 去 reference | reference model | ORPO（SFT 锚定替代 KL-to-reference）、SimPO（长度归一化对数概率替代）、KTO（未配对二值反馈，只需 2 模型） | 偏离 reference 的 KL 正则消失，需要靠 SFT 项或其他机制防漂移 |
| 去 reward model | reward model | 全部基于规则的 RLVR reward | reward 必须可自动判定，且规则仍会被格式作弊/测试泄漏攻击（Q2-43） |
| 都不砍，只降复杂度 | —— | PPO 自身：用一阶 clipped 目标代替 TRPO 的二阶 KL 约束，实现复杂度降低 10 倍 | 仍需 critic + reference |

🧭 **归纳（续）**：本章出现的最省显存组合是 **GRPO + 规则 reward**：只需 policy（+ 冻结的 reference 做 KL），比 PPO 的四份少两份；这也是第 12 章 Agent 训练主流配置的由来（Q2-71）。

## Q2-74 跨章对照：RL 训练的优化器与超参统一口径

- 章节: ch05 §5.9 + ch11 §11.15　（原文：[ch05](../00-原书档案/fulltext/ch05.md) / [ch11](../00-原书档案/fulltext/ch11.md)）
- 主题: RL 超参的共同约定

> 📖 **原文** (ch11 §11.15.8)：小LR、不用weight decay、恒定调度、FP32 master权重、激进裁剪。把正则化交给KL惩罚——优化器只管沿policy gradient前进，且不要冲过头。

> 📖 **原文** (ch05 §5.9)：init_kl_coef 0.01–0.1过低：reward hacking。过高：卡在SFT状态。

> 📖 **原文** (ch05 §5.9)：learning_rate 1 − 5 × 10 − 6过高：灾难性遗忘（Catastrophic Forgetting）。

> 📖 **原文** (ch11 §11.15.1)：•需要更小的更新：policy必须贴近reference模型（KL约束），所以学习率比SFT小10–100 ×。

🧭 **归纳**：把第 5 章的 PPO 超参表与第 11 章的优化器章节并起来看，RL 微调的共同约定是：

| 维度 | 共同口径 | 出处 |
|---|---|---|
| 学习率 | 比 SFT 小 10–100 倍；PPO/GRPO 约 1e-6，DPO 约 5e-7；过高 → 灾难性遗忘 | ch11 §11.15.1 / ch05 §5.9 |

| 调度 | 恒定（Constant / constant_with_warmup），短暂 warmup（PPO/GRPO 20 步，DPO 50 步） | ch11 §11.15.2 |

| 精度 | 必须 FP32 master 权重，否则 PPO/GRPO 常在 100–500 步后 reward 崩塌 | ch11 §11.15.4 |
